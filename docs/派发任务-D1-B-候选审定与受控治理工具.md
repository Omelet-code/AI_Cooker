## 3. 冻结执行与安全契约

- 默认dry-run；实际apply/rollback必须显式模式、准确目标标识和有效审批文件。测试仅使用Testcontainers/临时PG，禁止使用5433 cooker或启动IDE/运行服务。凭证从测试或环境注入，不打印、不写审批包。
- 同一批次事务先锁定目标与必要身份映射，按固定顺序避免死锁；重新校验公开归属、source/document/line ID、原文hash、旧结构化字段和词典映射前置条件。锁/校验后再写，任何漂移拒绝整批。不能只验证Markdown而忽略结构化事实已变化。
- 审批不允许任意覆盖newFields；重用同一解析器/固定提案规则核对，审批只选择候选和明确身份处理。禁止拼接动态SQL或把审批文字当SQL。
- 同请求键/同hash重放返回原结果、零重复写；同键异内容拒绝。部分失败回滚包括审计；并发重放、唯一约束冲突须测试。不得把异常吞掉当部分成功。
- 名称冲突优先复用逐组批准的规范ID；已有旧ID如果可能被历史/Mock引用，保留不删除。不新增虚构别名，不全表REVIEWED。新增规范身份也必须显式批准，名称已存在时不得盲目插入。
- 处理新增/移除/排序时保护唯一(recipe_id,sort_order)和旧行ID；未批准行的语义及来源不漂移，必要排序变化必须可审定和回滚。
- rollback只恢复自己成功应用的批次，锁后核对当前事实仍等于该批次after状态；有后续用户修改/依赖拒绝恢复，不覆盖新数据或删除被外部引用的新ID。重放已回滚批次不得静默重新apply。
- 报告保护原文、收藏、做菜记录和餐单/指导/采购快照；事实变化造成旧餐单CHANGED属正常保护，不能覆写历史来消除。输出实际影响recipeId及审计映射，供D1-C判断投影影响，不重建向量或伪标READY。
