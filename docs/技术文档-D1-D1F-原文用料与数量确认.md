# D1-D1F 技术说明：原文用料与数量确认

日期：2026-10-08

## 五种字段含义

| 概念 | 含义 | 页面处理 |
| --- | --- | --- |
| `rawName` | 保留的原始/候选用料名称 | 完整原文缺失时的回退名称，不据此解析数量或猜标准食材 ID |
| `rawLine` | 菜谱来源中的整行用料文本 | 优先展示，按普通文本插值，不作为 HTML 执行 |
| 结构化原量 | 服务端的 `amountMin`、`amountMax` 与单位字段 | 仅服务端明确给出数值时显示原量/范围；前端不扫描 `rawLine` |
| 人数折算参考量 | 服务端基于本餐人数与菜谱事实返回的 `referenceAmount` | 作为独立参考值展示；未知时保留服务端状态与原因，不覆盖原量 |
| 本餐确认量 | 用户在采购确认中主动填写并提交的 `confirmedAmount` 与单位 | 只代表用户确认的本次需求，不回写菜谱原文、结构化原量或食材身份 |

例如，`酱油 每个生蚝 1 ml` 中的 `1 ml` 可能是条件/比例文本。只要服务端数量字段为空，前端就显示整行原文并提示本餐总量待确认，不把 `1 ml` 当成整餐采购量。`姜 1 小块` 和 `生姜 1 小块（约 15g）` 同理，不提取或换算。若服务端明确给出 `300 克`，即使人数未知、折算参考量为空，也照常保留 `300 克` 并分开展示参考量原因。

## 前端实现层次

- `modules/recipe/format.ts` 是无副作用的视图格式化层。`formatIngredientSource` 负责原文回退；`hasStructuredIngredientAmount` 只判断后端数值字段是否存在。
- Vue 页面/组件负责按该判断选择文本行、数值列或简短待确认提示。Vue 插值会转义原文中的标签字符；不得改成 `v-html`。
- `ShoppingLines` 仍通过原有事件提交选择、数量和单位。数量输入校验及采购状态机继续留在原模块；本切片只调整显示条件。
- `KitchenMaterialsView` 的版本、来源、只读 GET 和代次隔离不变。未知汇总不重复显示为整餐数量，逐菜事实仍按原条目展示。

## 为什么不在前端解析原文

界面没有足够上下文判断数字是单份比例、条件用量、包装规格还是整餐总量。正则提取会把描述性数字误作采购数量；名称相似度也不能确认食材身份。数量、单位、折算状态和原因以服务端事实为准；无法确认时保留原文与未知状态，让用户在本餐采购步骤明确确认。

空的 `rawLine`、`rawName` 和展示名统一显示“原文未提供”。这表示来源文本缺失，不代表数量为 0、用户不需要该材料或可以省略确认。

## 安全与边界

- 所有菜谱原文和模型内容视作不可信文本；本实现只用 Vue 文本插值。
- 可选标识、原条目键、菜谱来源、CURRENT/CHANGED/UNAVAILABLE、历史只读和原请求隔离保持原行为。
- 原量缺失时，参考量未知的数字列隐藏；若已知原量，只隐藏不了解的参考总量，不隐藏原量。
- `confirmedAmount` 与结构化原量是不同事实。空确认量仍由既有服务端语义保留为未知，前端不改成 0，也不按名称匹配商品。
- 若服务端提供了数值但其条件语义尚未分类，当前展示层只保留该数值和服务端原因，不宣称前端已识别条件。
