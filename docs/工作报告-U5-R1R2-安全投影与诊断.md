## 3. 修复层级与契约边界

### 原事实与显示副本

新增 `policy/MealSafeProjection`，在两个 agent Service 中复用。递归复制 JSON：普通 `[链接文字](https://来源)` 保留链接文字、去除目标；裸 http(s)/www 地址只删除地址字符，不吞掉相邻中文操作。数量、ID、步骤序号和证据字段不裁剪。投影不抓取链接、不执行 HTML，不修改原 DTO 或数据库。

危险语义先检查原字符串，再投影：注入、诊疗、HTML、控制字符及危险链接方案直接抛带受控定位信息的 `Unsafe`，不会删除危险关键词洗白，链接目标含危险内容同样拒绝。剩余文本仍调用原 `safeText`；模型输出仍由原 MealPolicy/MealGuidePolicy 的类型、内容和证据规则检查，持久化层最后校验仍保留。

U3 候选摘要、新餐单菜谱事实与材料、U4 模型完整依据及服务器指导事实/材料使用相同投影。U3 在候选计数之前隔离危险候选，再计算菜/汤数量及一套/两套：剩余不足返回 NO_MATCH 澄清，不额外检索、不造菜。GUIDE 的已选危险依据整动作安全失败，选择和原餐单保留，不替换菜谱。

资格复核、材料再读取与指纹比较始终使用原 `MealRecipeFacts`，投影中的 sourceContentHash/factFingerprint 沿用原值，不重新哈希。所选依据变更或撤权依旧失败/隐藏。

**与旧“原文”约定的边界：原数据库、导入文档、原事实与原指纹继续保留原文；新餐单/指导模型数据及显示快照是安全投影，链接文字保留而目标不展示，因此显示文本不再是逐字原文。** 烹饪步骤、用量和证据引用不截断。T9/T14 旧 HTTP 契约未改，历史失败餐不自动修复或重跑；已有历史读保护仍执行。

### 诊断日志

新增 `policy/MealSafeDiagnostics`。候选隔离和已登记动作执行失败使用 WARN，输出固定事件、conversationId/mealId/actionId、类型/版本、服务端阶段、安全错误码和异常类名。投影危险内容增加原 recipeId、受控字段路径及规则类别。

只把这些元信息交给 logger，异常对象不作为 Throwable 参数，不打印 message、cause、栈、正文、Prompt、原模型响应或秘密。未知 API 异常在日志中归一为 EXECUTION_FAILED；HTTP 响应保持既有固定码。模型输出边界无法可靠定位菜谱时明确记录 recipeId=null / model.output / OUTPUT_BOUNDARY，不猜测具体菜谱或字段。登记前认证/参数/状态拒绝沿用原 HTTP 处理，不新增业务字段或全局异常日志。

## 6. 教学与预防

原事实相当于数据库实体和变更凭据，安全投影相当于特定业务展示 DTO。它们可以有不同文本，不能互相替代身份、权限和指纹。修复应落在餐单/指导编排及专属 policy 边界，全局删 URL 或改导入会影响既有检索和旧接口。

隔离必须在计数之前，否则模型收到的候选数量与服务器实际允许集合不一致；不足要明确澄清，而不是偷偷扩调用或换菜。已选套餐不同于候选池，用户决定不能由失败恢复逻辑擅自更改。

日志调用 `warn("失败", exception)` 会输出异常链；异常 message 即便看似诊断信息，也可能包含密钥或 Prompt。本次只提取受控类名、阶段和字段定位，日志捕获测试验证正文、模拟 Key、Cookie/Authorization 和 cause 不出现。定位元信息只在服务端日志，不扩展 HTTP 返回。

预防本类问题：每个新模型/展示数据入口区分“原始事实”和“安全显示副本”，用真实 Service+隔离 PG 链路同时检验普通来源与危险来源、资格复核、序列化历史和同键重放，不能只测试一个正则函数。保留现有资源/权限回归作为边界证据。
