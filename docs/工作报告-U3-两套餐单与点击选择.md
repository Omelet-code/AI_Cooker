## 3. HTTP 与数据库

路径统一带 `/api/conversations/{id}/meals`：POST 创建、GET 分页；`/{mealId}` GET 详情；`/{mealId}/revisions` POST 修订；`/{mealId}/selection` POST 选择；`/{mealId}/actions/{actionId}` GET 动作。

新终态201，执行失败也返回201并提供 action.error；同键终态或同方案连点200，在途同键202及 Location。非法原始 JSON 类型/未知字段400，越权404，版本/参数/不同方案冲突409。默认执行关闭时新创建/修订503且零登记，旧重放和选择仍可处理。沿用 Cookie、CSRF、ApiResponse、no-store。

V11 新建 meal_session、meal_action、meal_option。关系字段保存归属、版本、状态、请求 UUID、deadline；JSONB 保存验证后的需求/事实/材料/结果。复合外键约束会话/餐/用户一致和所选方案属于当前版本；部分唯一索引限制一餐仅一个在途动作。参数 SHA256 与参数对象、精确原文同时比较，不只信任哈希。

短事务按 conversation→meal→action→option 加锁。登记/开始提交后在事务外等待网关和候选；最终方案、餐视图、动作终态一起提交。修订登记时递增版本、清除选择；失败仍保留新版本 FAILED。后续新写在锁内恢复过期动作为 RUNTIME_INTERRUPTED，GET 不恢复；迟到完成不得覆盖新版本。

读、重放和选择不调用 ModelGateway、MealCandidateService、T5 或凭证解密；允许调用纯事实/资格 Service。回读标记 CURRENT/CHANGED；不可见或删除则 UNAVAILABLE，并隐藏整份 options。提交和选择再次核验指纹与硬资格，包括可能不进入事实指纹的食材别名变化。
