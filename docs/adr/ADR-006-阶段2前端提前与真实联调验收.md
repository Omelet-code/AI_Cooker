# ADR-006：阶段 2 前端提前与真实联调验收

- 状态：已接受（2026-09-30 用户已授权创建两个实现会话并按既定顺序推进至 T10）
- 日期：2026-09-30

## 背景

用户要求阶段 2 结束前可在前端与后端真实交互，计划一个后端会话与一个前端会话并行开发。原计划把页面集中到阶段 4，无法提前验证认证、收藏和做菜历史交互。

## 候选方案

1. 页面仍在阶段 4 集中实现：后端先行简单，但认证 Cookie 和页面交互问题暴露较晚。
2. 前后端各自并行、联调时再对字段：开工快，但契约分歧会扩大返工。
3. 先冻结共享契约，再按登录→收藏→做菜逐步开发并真实联调：保留并行收益，同时每个切片可审查。

## 决策与理由

采用方案 3。阶段 2 增加最小登录注册、真实菜谱列表和详情、收藏及做菜历史/评分页面；新增普通菜谱读取 API 供页面选择菜谱，不依赖尚未开发的 Agent 或收费向量查询。前端在接口未就绪时可显式使用固定 Mock，签收必须切换 real 并通过 Spring Boot 写入 PostgreSQL。

统一 s2-api-v1 定义字符串 ID、可空字段、分页、HTTP 错误、CSRF、Cookie、续期和完成事件幂等。一个后端会话使用 `gpt-6-sol` / `medium`，前端会话使用 `gpt-6-luna` / `high`。主架构维护共享文档，两个实现会话分别修改 backend 和 frontend，分项验收、按授权领取下一任务。

## 影响

- T9 扩展为真实菜谱读取与收藏；前端新增 F2-A～F2-C；T11 必须收齐浏览器真实交互、持久化与用户审定证据。
- T8 Key 加密保存仍属阶段 2 的后端接口能力，设置页在 Agent 阶段接入。
- 阶段 4 转为全产品页面打磨和 Agent/购物联调；MVP 截止日期不变，排期按实际验收进度调整。
- 任务模型偏好与架构确认不自动授权会话创建或编码；派发前仍按 AGENTS 冻结并取得具体任务授权。

## 复审条件

- 最小前端阻断后续 Agent 进度，或接口范围扩大到聊天/购物；
- 需跨域认证、移动客户端或更复杂前端组件库；
- 真实联调出现契约缺失，需要主架构统一变更版本。
