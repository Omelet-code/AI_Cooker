# ADR-001：先模块化单体，后演进微服务

- 状态：已接受
- 日期：2026-09-25

## 背景

项目需要在 2026-10-05 前完成可演示 MVP，同时承担学习 Spring Cloud 的目标。首期业务边界和外部采购接口尚在验证中。

## 候选方案

1. 一开始直接拆分微服务。
2. 使用无边界的普通单体。
3. 使用按业务模块隔离的模块化单体，稳定后按模块拆分。

## 决策

采用方案 3。

后端首先作为一个 Spring Boot 进程和一个 PostgreSQL 实例运行，但按 `identity`、`conversation`、`recipe`、`retrieval`、`agent`、`pantry`、`shopping`、`policy` 划分业务模块。

## 理由

- 优先完成真实业务闭环。
- 降低分布式事务、服务治理和部署对学习节奏的干扰。
- 模块边界可直接作为后续服务拆分候选。

## 影响

- 跨模块只能通过 Service 接口或明确的应用事件协作。
- 不允许跨模块直接调用 Mapper。
- Spring Cloud、Nacos、Gateway 和 RabbitMQ 后置。
