# ADR-007：接受记住我Cookie已知偏差

- 日期：2026-10-01，Asia/Shanghai。
- 状态：用户明确接受，暂不修复；2026-10-02其他T11证据及用户浏览器确认齐备后阶段二已签收，偏差并未因此修复。

## 背景

T11发现未勾选rememberMe时COOKER_ACCESS仍持久900秒；COOKER_REFRESH则是非持久Cookie。旧验收要求两枚认证Cookie均非持久，当前实现与该要求存在偏差。用户在理解JWT15分钟与续期24小时/30天的区别、关闭浏览器及恢复会话的限制后，明确表示“可以不用修复，继续推进”。

## 候选方案

1. 按旧契约修复访问Cookie，未勾选时省略Max-Age/Expires；需要实现及回归，但仍无法控制浏览器会话恢复。
2. 暂时接受现有15分钟访问Cookie行为，保留续期规则和安全控制，继续T11验收。
3. 强制保证每次关闭浏览器后重新登录：需要另行定义浏览器生命周期和认证协议；不能靠beforeunload可靠实现，不属于当前任务。

## 决策及理由

采用方案2，依据用户明确选择。访问Cookie现有900秒属性保持不变；未勾选续期Cookie非持久、服务端最长24小时；勾选续期Cookie持久、最长30天。JWT本身仍15分钟有效，续期原子轮换且受绝对截止限制。

Cookie问题记为用户接受的已知偏差，不再单独阻断T11，不记为“修复完成”或“旧要求测试通过”。不派发修复，不修改业务代码、配置时长或CSRF/Cookie保护。复审发现的事实和历史证据保留。

## 影响与限制

- 未勾选且关闭浏览器后，未过期的访问Cookie可能继续提供登录身份；超过其剩余有效期后能否恢复取决于续期Cookie是否保留。
- 浏览器恢复会话可能保留非持久续期Cookie，不能承诺15分钟后必然重新登录，也不能承诺关闭浏览器等于服务端注销。
- 退出按钮仍应清Cookie并撤销当前续期凭证；已签发JWT在自身到期前仍可能有效。
- 不削弱HttpOnly、生产Secure、SameSite、CSRF、密码哈希、用户隔离或凭证认证加密。
- 接受该偏差本身不等于接受其他未验项；稳定密钥、V7及真实HTTP重启证据随后完成，2026-10-02用户明确确认浏览器5项全部通过后才签收阶段二。当前仅阶段三架构讨论，未新增实现/派发、收费调用及提交合并授权。

## 复审条件

用户重新要求关闭浏览器后严格重新登录；面向共享设备或对外正式部署；安全要求提高或登录协议变化。届时重新取得具体授权并设计验证，不从本次接受决定推定永久豁免。
