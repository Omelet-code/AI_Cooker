# ADR-010：固定RAG推荐与结果快照

- 日期：2026-10-02。
- 状态：T13签收后，按用户“检验并推进”冻结本次T14；尚未实现/部署/真实收费验证。
- 精确契约：`docs/阶段3-T14固定推荐契约.md`，派发边界见T14专属任务卡。

2026-10-03新增决策：用户要求两套整餐、默认人数、点击后依据生成及小厨人设，见ADR-011。本文固定模板/最多3推荐保留为旧接口与历史基线；新餐单使用独立版本，不将新增自由讲解伪称已被旧验收覆盖。当前仅架构准备，没有实现/收费允许；下方尚未实现/部署状态是原冻结时记录。

## 选择与理由

1. 固定理解→检索→选择→校验→持久化，复用T12网关与T5生产Service；不引入新框架或自主工具循环。相比一次模型自由回答，两次结构化调用可审查约束/真实候选；相比工具循环，调用上限和学习负担更可控。T15另行推进工具与SSE。
2. 同步POST先完成后返回201；终态重放200、在途重放202只读。原阶段三202草案是异步方向，不用于伪装同步执行；新只读recommendation接口不改变T13 TurnView。前端等接口稳定后另派。
3. 模型不生成可直接展示的任意事实/健康文本。只允许当前候选ID和可证实理由码；菜名等来自详情Service、中文解释由模板生成。较自由自然语言牺牲表达丰富度，换取MVP可验证性；RAG不能只凭Prompt承诺无幻觉。
4. 五类约束用KEEP/SET/CLEAR及当前原文证据；SQL硬过滤复用现有可表达条件，预算/已有食材保留意图但不伪称满足。上一有效约束从用户/会话成功快照读，而不是无限消息重新提取。
5. 新增V9的conversation_recommendation结果表；归属/版本为关系列，有限业务对象为JSONB。相对只存助手文本，快照可回读卡片与指标；相对保存原始供应商响应，避免无用内容/敏感材料。ASSISTANT、快照、终态、会话时间同短事务，跨模块只用Service。

## 资源与证据限制

T12现有单次连接/读取超时不是传输总deadline。T14不另启线程假取消，90秒为外部阶段前后软检查；最多2网关/1检索、T13DB120秒禁止迟到成功仍有效。没有验证前不能宣称90秒墙钟必结束；真正异步终止/全局容量限制后续专项验收。

执行开关默认关闭；测试只替换模型/向量外部依赖，生产检索Service与真实PG必须执行。真实启用/收费、工作树提交整合和开发部署均不是本次允许范围。

指标区分网关方法尝试与供应商计费请求；缺usage/Embedding实发计数为未知，不估0或复用T6数字。失败轮次暂无完整费用持久化统计，阶段三集成指标仍需后续设计与验收，不从成功快照推导全体成本。

教学继续讲清DTO校验、有限上下文、JSONB/关系字段、短事务/RAG及确定性输出的代价，不能将测试签收冒充真实模型推荐或用户学习签收。
