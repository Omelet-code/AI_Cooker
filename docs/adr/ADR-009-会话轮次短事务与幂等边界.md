# ADR-009：会话轮次短事务与幂等边界

- 日期：2026-10-02。
- 状态：T13架构冻结；用户在明确T13下一步后回复“继续推进吧”，本次仅授权T13实现。尚非实现、部署或收费验收证据。
- 精确契约：`docs/阶段3-T13会话与轮次契约.md`。

## 背景

聊天历史是用户业务数据；模型请求属于可能收费且不可纳入PG事务的外部动作。重复点击/认证重放/网络失败后重试必须指向同一轮次，不能凭前端禁用按钮或内存锁保证；跨用户归属必须在后端与数据库保持一致。

## 选择与理由

| 方案 | 特点 | 本次判断 |
|---|---|---|
| 单机锁/内存状态 | 学习和代码少，但进程重启丢状态，多实例无保证 | 不作为幂等与互斥依据 |
| 会话父行锁+唯一约束+条件状态更新 | 短事务可审查，跨进程共享PG事实，操作顺序明确 | T13采用 |
| 全局Serializable/分布式锁/持久队列 | 可以处理复杂协调，但增加重试、运维与学习负担 | 当前不引入 |

数据库行锁只围绕登记/状态变化，模型调用留事务之外。部分唯一索引兜底每个会话最多一个在途轮次；requestId唯一键和原文比较决定同键回读或冲突。状态只前进到终态，不原地重跑失败轮次。

可信身份只取CurrentUserService，conversation不依赖agent；后续agent只调用conversation的Service，不操作Mapper。普通用户接口只读写自己的会话；状态修改和恢复没有客户端HTTP入口。

T13只开放会话创建与读取，以及测试可验的内部轮次能力。发送消息HTTP及编排留T14，避免生产环境假回复或无执行器的PENDING。T13不预先写任意JSONB，等T14确定约束/候选/usage后追加版本化迁移。

## 过期与后续影响

登记设120秒截止、开始不延长；开始/成功更新检查截止和状态，过期恢复只标失败不自动重放。当前在登记或显式内部恢复时处理过期轮次，不新增启动/定时全库扫描；GET不恢复。因此只通过过期状态测试不能声称真实进程重启或后台恢复调度已验收。

此保证不等于供应商收费恰好一次。T14需要冻结同步执行接线、资源预算与错误映射；T15再处理异步可信身份、恢复调度和SSE，不能自行复制Key到共享线程或依赖SecurityContext自动传递。

模型候选、费用、采购迁移顺序未在本ADR冻结。实现不符契约时先报告，不通过关闭CSRF、跳过PG并发测试或引入另一套ORM来完成。

设计依据已核对：[PG18行锁](https://www.postgresql.org/docs/18/explicit-locking.html)、[部分唯一索引](https://www.postgresql.org/docs/18/indexes-partial.html)、[READ COMMITTED](https://www.postgresql.org/docs/18/transaction-iso.html)。本项目实现效果以隔离PG/HTTP测试和主架构独立复审为准。
