## 2. 每份文档必备内容

1. **先解释业务与边界**：用实际用户操作说明实现什么；提供 30 秒项目介绍和约 2 分钟技术讲述示例，严格区分已实现、未实现、未来演进。
2. **代码地图**：按 controller/service/impl/mapper/entity/dto/vo 画出目录树；列出本次主要类、方法、Mapper XML 和 Flyway 文件，以及职责与依赖。用实际文件和方法作为阅读入口，不能只复制通用分层概念。
3. **完整请求与数据流**：选择至少一个成功请求，从浏览器/安全过滤器/Controller/Service/Mapper 到 PostgreSQL、再到 VO 响应逐步讲清；给简短时序图或流程图，说明每层输入输出和事务位置。
4. **关键实现**：解释真实核心方法、SQL、唯一约束、锁或原子更新。使用短代码片段配中文解释，指出为何这样写、错误写法会产生什么现象、如何用测试证明。不能用伪代码掩盖实际实现与设计的差异。
5. **技术栈与取舍**：列出本任务真实依赖及版本、使用点和原因；对主要设计给至少两种方案比较。以用户熟悉的 Spring Boot + MySQL 为参照，解释 PostgreSQL、Flyway、Spring Security 等新增概念，不把本任务未用到的 Cloud/MQ/Agent 框架列作实现亮点。
6. **数据与失败路径**：表字段/索引/约束的作用、一次写入如何落库、至少三种失败或并发场景，异常如何映射为 s2-api-v1 的 HTTP/code；说明安全边界、性能影响和真实限制。
7. **测试和复现**：给已运行命令与结果，说明关键断言证明了什么；提供不依赖收费 API 的复现步骤、代表性 SQL/API 请求。密码/密钥/认证 Cookie 只使用虚构占位，不能复制本机凭证。
8. **面试追问**：每项至少 8 个与真实代码相关的问题，每题包含简短回答、原理展开、面试官可能继续追问的内容、可定位的代码或测试证据。不得宣称不存在的性能数据或线上规模。
9. **学习清单与自检**：把新概念分为当前必须理解和后续深入；提供官方资料。给至少 5 道不用照抄答案的自检题和 2 个最小练习，最后附答案要点或检验方法。

## 3. 各任务重点

### T7

讲清 Spring Security 与传统 MVC 拦截器的职责区别；密码哈希与 JWT 签名；访问 JWT 与随机续期令牌；记住我为何需要服务端状态；Cookie 的 HttpOnly/Secure/SameSite 与 CSRF；签发方/受众/到期校验；续期并发轮换；退出只能撤销续期、不保证所有访问 JWT 立即失效的边界。追问必须涉及“为什么不用长期 JWT”“JWT 为什么仍会访问数据库”“403 与 401 如何区分”。

### T9

讲清真实菜谱读取如何复用导入数据，普通菜名查询与混合检索的区别；字符串 ID 与 JavaScript 整数精度；DTO/VO/Entity 区别；空值为何不能捏造；分页排序如何稳定；用户可见性为何不能只靠前端；收藏唯一键和幂等添加/删除；SQL 参数化与 LIKE 转义。追问包括重复收藏、越权请求和 N+1 查询。

### T10

讲清一次烹饪事件与累计次数的区别；客户端 UUID、服务端唯一约束和事务如何共同实现幂等；同键不同内容为何返回冲突；并发插入和重试如何处理；最近非空评分与最新事件为何不同；数量与展示熟悉度的产品语义；同一道菜如何真正做第二次。追问必须包含“为什么禁用按钮不够”“事务失败后如何保证重试”“怎样防止网络超时后重复计数”。

## 4. 理解程度的检验方法

目标是用户能够不看文档复述完整请求流、定位关键代码、解释选型取舍，并用本项目测试或 SQL 说明边界；不能仅靠背术语。每项建议自检：独立画一次数据流；回答至少三道追加追问；执行一个并发/失败复现实验；指出一个可以改进的设计及其代价。实际掌握情况由用户练习与主架构后续问答评估，不能用“文档已写完”替代。

主架构审查每份文档的代码一致性、可复现性和面试答案事实性。如技术文档不符合本交付要求，应在已授权任务范围内补齐，不能开始新增功能来掩盖缺项。
