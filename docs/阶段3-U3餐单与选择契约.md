# U3 餐单与选择契约

日期：2026-10-04。版本 `kitchen-meal-v1`。本卡工程终审覆盖 U3，不覆盖 U4/UF2 或真实收费验收。完整后端集成回归通过后才派发。

## 1. 目标与归属

自然语言理解 → U2 分角色候选 → 模型选出最多两套不同组合 → 服务器补真实材料并保存 → 鼠标点击确定一套 → 只读回看。

- `agent`：新餐单 Controller/Service/impl、严格模型 DTO、两次同步编排；依赖公共 Service，不访问其他模块 Mapper。
- `conversation`：新餐/动作/方案的关系约束、版本和 JSONB 快照，公共 DTO 不依赖 agent 类型。保留旧 ConversationService/Turn/消息/推荐 API。
- `policy`：本餐输入/模型结构/事实选择/展示文字规则及 xiaochu-v1，模型不直接提供权威菜名、材料或用量。
- 复用 U1 档案、U2 MealCandidateService/RecipeMealFactsService、T12 ModelGateway；不改身份、recipe/retrieval、旧 T14 生产代码或网关限制。
- 不写旧 chat_message/turn 的假餐单回复。新历史使用下列 meals API，旧 F3-B 页面暂保持原行为。U3 的点击只持久化选择，**零模型调用且 guide=null、guideAvailable=false**；不开放生成指导的收费入口。

## 2. 输入与人数

正文保留精确原文，非空白、最多 4000 Unicode 码点。UUID 采用既有规范格式，ID 为正 BIGINT 十进制字符串，不在前端转 Number。写请求严格拒绝未知字段和错误原始 JSON 类型。

人数仍正 32 位整数；本餐表单/正文显式人数优先于新餐登记时读取的档案，来源 EXPLICIT/PROFILE。表单与正文明确人数冲突先澄清，不静默取舍。新餐无人数来源返回 CLARIFICATION，不猜 2 或 3～4；缺人数时最多一次理解调用，无候选/组餐调用。修订未提供新人数沿用本餐快照，不重新读取档案追改旧餐；明确修订可覆盖人数并产生新版本。

本次每套菜数 dishCount=0～8、汤数 soupCount=0～4，合计 1～10；两者未明确时澄清，不能默认四菜一汤。限制是工程资源上限，不是人数/饮食建议。整餐总耗时与单菜时间必须区分；本阶段只支持可明确解释为单菜上限的 1～1440 分钟，整餐完成时间要求返回 TIME_SCOPE_AMBIGUOUS，不冒充已满足。

厨具 null 表示未限制，[] 表示明确没有厨具；排除食材、已有食材各最多20项/每项80码点，去首尾空白和重复但保留 null/[] 语义。预算为十进制字符串 0～10000、最多2位小数，用 BigDecimal，只保存软条件、不核价。默认排除/已有食材为空，时间/预算/厨具未知为 null。

创建不带旧会话历史/旧餐约束。修订只提供当前餐上一成功或澄清需求快照和本次正文，由字段变更显式更新；不做跨餐长期记忆、不实现任意局部换菜。

## 3. 模型结构与提示词

两次均用 T12 JSON 模式，System 明确写出完整 JSON 结构、必填/可空字段、字段类型/枚举/长度及输出 JSON 要求；用户/快照/候选均标为不可信数据，不提升为 system 指令。不允许任意工具、地址或 Key。

第一次输出固定结构：

```text
{
  intent: "MEAL_PLAN" | "CLARIFY" | "UNSUPPORTED",
  mode: "RANDOM" | "SEMANTIC" | null,
  query: string | null,
  changes: {
    dishCount, soupCount, diningCount, maxCookingMinutes,
    availableToolNames, excludedIngredientNames, availableIngredientNames, budgetYuan
  },
  clarificationCodes: string[]
}
每个 changes 字段必须出现，为 { action: "KEEP"|"SET"|"CLEAR", value: 类型或null, evidence: string|null }
```

SET/CLEAR 要求当前原文精确存在的非空 evidence≤200码点，KEEP 的 value/evidence 为 null；SET 严格符合字段类型，CLEAR 的 value=null。初始 dish/soup/dining 为未知，修订 KEEP 取当前餐值；CLEAR dish/soup 变未知、dining 回到本餐登记时档案快照（没有则未知），其他回默认值。证据存在不等于理解必然正确，固定样例验证数量/随机与时间歧义。表单人数不是模型可覆写事实。

MEAL_PLAN 要求数量/人数完整合法；RANDOM query=null（调用 U2 时转空字符串），SEMANTIC query 为1～1000码点真实偏好，不把“四菜一汤”等数量当关键词。未满足前置条件由服务器降为 CLARIFICATION，不执行候选。澄清码仅 COUNT_REQUIRED、DINING_COUNT_REQUIRED、DINING_COUNT_CONFLICT、TIME_SCOPE_AMBIGUOUS、REQUEST_AMBIGUOUS；最多4个，固定中文提问。指定单菜或指导意图本卡返回 UNSUPPORTED 并提示使用旧菜谱入口，不强行组成一桌；新增专门定位/指导能力后续另定。

候选取得后，第二次仅允许：

```text
{ options: [{ recipeIds: string[], explanation: string }] }
```

options 长度1～2；每套 ID 必须为本次候选子集、满足准确角色/数量且无重复；两套不能是同一集合换顺序，组间可部分重合。explanation 为非空纯文本≤200码点，可采用“小厨”自然语气，但不提供步骤、材料、份数/分钟/价格/营养数值或诊疗断言；权威字段始终由服务器装配。安全策略需检查所有外发文本字段（包括候选原名称/原料/步骤），不能仅过滤 answer。原数据不被覆盖；不可安全展示的数据以安全失败处理，不能把删去关键原料的材料清单当完整事实。

严格拒绝未知字段、尾随 JSON、标量自动转换（如4.9→4）、重复/越界 ID、错误数量及空说明。模型不合法终止该动作，不额外收费纠正或自动补方案。

## 4. 候选、材料与资源

每个非零角色 candidateCount=min(20,max(2×所需数,所需数+4))，最多两组/总40；0角色不请求。复用 U2 RANDOM/SEMANTIC 模式及资格过滤，单菜有时间上限排除未知时间。随机种子为服务器登记并保存的 signed long，不由模型生成，不用空 query 走 T5。SEMANTIC 每角色至多一次 T5，保持融合排名；不足不追加调用。

按角色候选数无法凑一套时，在第一次理解后结束 NO_MATCH；候选总集合只有一种组合时最多一套并提示 ONLY_ONE_OPTION。足够多样候选则要求两套，模型只给一套不能伪装完整成功，应判 MODEL_INVALID_RESPONSE；不得自动再调用。RANDOM/不同动作不保证组合完全不同，但成功重放保持同种子/同方案。

每次模型输入保留网关≤16消息/20000码点，输出仍2048 tokens，不扩网关/依赖。方案阶段候选仅输入 ID、角色及规则、名称≤100码点、类别、已知份数/单菜时间和材料名称摘要（最多10个、单项80码点，明确“摘要非完整清单”）；完整材料保存在服务器而非送给组餐模型。名称等摘要越限可省略非必要文字并标摘要不完整，但不得截断用户当前原文、硬约束/ID/角色，也不能用摘要声称食材齐全。必需输入仍超限则 RESOURCE_LIMIT，无隐式多次拆分。

服务器调用 U2 materials 获取每套完整原材料、参考折算、待确认和来源。提交前重新核验所有候选子集/角色/硬资格/可见性及 factFingerprint；材料返回的事实指纹也须与选中事实一致，变化则失败 MEAL_FACTS_CHANGED，不悄悄替换。两套 materials 分别最多10道，未知份数/区间/单位保留，不由模型填写或换算。

创建/修订每动作最多2次 ModelGateway、最多2次候选语义调用；随机候选0次 T5/Embedding，但理解/组方案仍可能调用 LLM。同步阶段软预算90秒、DB截止120秒，阶段前后检查；超限不再调用/提交成功，不承诺硬网络取消。选择、GET及终态/在途重放零模型/检索/解密凭证；GET可调用纯事实 Service 检查权限/版本，不调用 MealCandidateService。

动作 metrics 保存 modelGatewayAttempts、candidateServiceCalls、semanticSearchCalls、queryEmbeddingRequests（未知null，随机确定0）、逐尝试 usage（未知null）、durationMs。方法尝试不等于供应商实发/计费，失败不冒充免费，不存完整 Prompt、原始输出、异常链或 Key。

## 5. 精确 HTTP 与响应

沿用 ApiResponse、Cookie/CSRF、no-store 和 UTC 时间。新接口不接受 userId、Key/模型地址或客户端材料事实。

| 方法/路径（包含 /api） | 请求/响应 |
| --- | --- |
| POST `/conversations/{id}/meals` | `{requestId,content,diningCount?: number|null}` → MealActionView |
| GET `/conversations/{id}/meals` | page=1,size=20≤50 → 既有 Page 形状，items 为 MealView |
| GET `/conversations/{id}/meals/{mealId}` | → MealView |
| POST `/conversations/{id}/meals/{mealId}/revisions` | `{requestId,expectedVersion:number,content,diningCount?:number|null}` → MealActionView |
| POST `/conversations/{id}/meals/{mealId}/selection` | `{requestId,expectedVersion:number,optionId:string}` → MealActionView；只保存选择 |
| GET `/conversations/{id}/meals/{mealId}/actions/{actionId}` | → MealActionView；不恢复/执行动作 |

表格路径前统一加 `/api`。新同步创建/修订/首次选择终态201（执行失败亦201、action.error说明）；同键同输入终态或已选同一方案200、在途同键202+Location动作读取URL。校验400；不存在/越权404；同键异输入、版本/不同方案冲突或本餐其他在途动作409。使用原身份/CSRF错误规范。

Model 执行沿用默认关闭 `cooker.agent.execution-enabled=false`，不另开配置或启动真实服务。关闭时合法新的创建/修订503 AGENT_EXECUTION_DISABLED、零落库/调用；已存在同键原输入重放和零模型选择仍可读/处理，不因关闭擅自重新执行。测试显式开启并使用外部替身。

```text
MealView {
  schemaVersion: 1, id, conversationId, version: number,
  status: "PENDING"|"CLARIFICATION"|"OPTIONS_READY"|"SELECTED"|"FAILED",
  diningCount: number|null, diningCountSource: "EXPLICIT"|"PROFILE"|null,
  requirements: {dishCount,soupCount,mode,query,maxCookingMinutes,availableToolNames,
                 excludedIngredientNames,availableIngredientNames,budgetYuan},
  answer: string, options: MealOptionView[], selectedOptionId: string|null,
  factsStatus: "CURRENT"|"CHANGED"|"UNAVAILABLE",
  noticeCodes: string[], guide: null, guideAvailable: false, createdAt, updatedAt
}
MealOptionView { id:string, ordinal:1|2, explanation:string,
  dishes: MealRecipeFactView[], soups: MealRecipeFactView[], materials: MealMaterialsView }
MealActionView { action: { id,mealId,requestId,type:"CREATE"|"REVISE"|"SELECT",
  version:number,status:"PENDING"|"RUNNING"|"SUCCEEDED"|"FAILED",
  createdAt,startedAt,finishedAt,error:{code,message}|null,metrics }, meal:MealView }
```

MealRecipeFactView/MealMaterialsView 的业务字段语义按 U2 DTO 完整映射，**所有 long ID 为字符串、BigDecimal 为十进制字符串**，保留null、原量/行/步骤/来源及needsConfirmation，禁止裸返回Entity或默认Jackson数值long。字段名按U2，不能丢关键原材料/步骤以规避大小限制。requirements 未确定数字允许null，合法0有别于未知。

answer由服务器按状态简短组装；OPTIONS_READY提示选一套，SELECTED明确“已选定，详细指导尚未开放”，不冒充生成指导。noticeCodes 固定：ONLY_ONE_OPTION、PREFERENCE_NOT_GUARANTEED、BUDGET_NOT_VERIFIED、AVAILABLE_INGREDIENTS_NOT_INVENTORY、MATERIALS_REQUIRE_CONFIRMATION、GENERAL_DIET_ONLY及FACTS_CHANGED/FACTS_UNAVAILABLE按事实适用。

所有详情/列表/动作回读均重新检查被引用菜谱权限，不以历史快照授予权限。全部可见且事实相同 CURRENT；事实变更但仍可见 CHANGED，返回已保存历史事实并明确旧版本、选择拒绝；任何相关菜谱不可见/删除则 UNAVAILABLE，整份 options=[]、不外发旧菜名/材料/说明，保留当前用户餐/动作安全元信息和固定通知。GET不改变存储状态，不重算方案，不写恢复终态。

## 6. 持久化与并发

只新增 conversation 的 `V11__create_meal_planning.sql`，不改V1～V10。关系字段与数据库约束：

- `meal_session`：BIGINT identity、conversation_id/user_id复合FK、登记档案人数快照、当前人数/来源、current_version正数、status、selected_option_id nullable、创建/更新时间；UNIQUE(id,conversation_id,user_id)。
- `meal_action`：BIGINT identity、meal_id/conversation_id/user_id/version、request_id UUID、type/status、原输入 TEXT/规范参数 JSONB及SHA256、seed nullable、deadline/started/finished、有限结果/metrics、安全错误码。复合FK绑定归属；UNIQUE(user_id,conversation_id,request_id)，规范哈希包含动作类型、目标meal/版本、原文/人数或optionId，排除requestId；原参数同时比较，不仅比较哈希。活动动作按meal_id建部分唯一索引（PENDING/RUNNING）。
- `meal_option`：BIGINT identity、meal_id/conversation_id/user_id/version、ordinal 1/2、schema_version=1、有限JSONB事实/材料/解释及指纹。UNIQUE(meal_id,version,ordinal)，复合FK；selected_option绑定自身餐/当前版本/用户/会话，不能引用别人/旧版本。可增加必要复合唯一条件支撑FK。
- 可变 requirements/option/结果为对象 JSONB，版本/归属/状态/请求键不能仅放JSONB。每方案序列化≤256KiB、每动作结果快照≤512KiB（UTF-8）；超限失败，不截断真实材料。只存验证过的业务对象，不保存原始模型内容。

锁顺序固定 conversation父行→meal→action→option，均短事务；先登记/唯一开始→事务外理解/候选/组方案→最终短事务原子保存方案、结果、终态及更新时间。选择只一次短事务。conversation更新时间随写变更，不改旧next_turn_no/sequence；同会话旧T14与新餐通过相同父锁协调写事务但不共享历史上下文。

同键重放先核原参数，再判断版本/执行开关，返回既有动作与**其对应版本的历史结果**，不能误读新版本冒充旧请求结果；权限与事实保护同GET。CREATE规范输入只含动作类型、会话及客户端正文/人数，不含尚未分配的mealId/seed；REVISE/SELECT另含客户端目标mealId/expectedVersion等，不把新生成ID带入重放比较。expectedVersion须为正32位整数，版本递增检测溢出。新修订 expectedVersion 精确CAS，登记接受时 current_version+1、清除选定/旧可选状态，旧方案仍为历史，不再可选；修订失败保持该新版本FAILED、不悄悄恢复旧按钮。PENDING阶段无可选方案。

同版本同时选择不同方案最多一个成功；同方案不同新键重复点击返回原成功选择动作200，不创建/执行新动作；不同方案409。同键异option/version仍409。同键SELECT可重放，不能因expectedVersion已过期而重执行。新版本拒绝旧选项。

过期动作由后续新写请求在锁内安全失败恢复 RUNTIME_INTERRUPTED，GET不恢复；状态更新遵守期限及一次开始资格，迟到结果不写成功。遇DB落库失败不以内存结果伪装成功，无自动新键/模型重试。业务失败码最少包括既有模型/检索/资源安全错误及 MEAL_FACTS_CHANGED；错误固定中文，不回传供应商正文。

## 7. 验收与学习

真实认证/CSRF/HTTP/Service/Mapper/隔离PG，模型及Embedding替身，不Mock全部内部能力：至少一组 RANDOM 用真实 U2、另一组 SEMANTIC 用真实 U2/T5且仅替身 QueryEmbedding；T12网关协议测试保留。

必须覆盖：四菜一汤两套数量/角色与材料；仅一套/不足一套/未知角色；默认/显式/缺失/冲突人数与档案变更不追改；新餐无旧约束、修订/旧键重放；严格JSON类型/未知字段/重复和越界ID/假时间/安全文本；A/B所有读写与复合FK精确23503/合法正例；并发同键/异键/不同方案/同方案连点；成功快照事务回滚、期限/软预算及外部等待无事务；所有GET/重放/选择零模型，关闭新生成零落库，事实变更/撤权在提交和回读均安全；跨完整应用上下文重建回读；V10→V11保留数据和旧接口回归。

完整非收费Java21离线回归、实际Docker隔离PG和打包，不跳过关键回归或真实收费测试。教学文档须讲解真实分层/调用流、SQL唯一/FK/CAS与事务、JSONB/BigDecimal、模型约束和局限、未知结果/费用边界，对照Spring Boot/MySQL；至少8个面试追问、5自检、2练习。未学习技术单独列出，不能保证读文档就已掌握。
