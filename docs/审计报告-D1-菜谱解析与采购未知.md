## 3. 根因与确定性复现

### 3.1 名称和数量解析

`HowToCookMarkdownParser.AMOUNT`主要支持“名称 空格 阿拉伯数字 单位”。`小龙虾 = 2 斤`中的等号留在名称；`香叶 = 两片`、`姜，13g。`无法匹配时，降级把整行去掉括号作为名称。导入器仅去括号、规整空白后创建UNREVIEWED词典项，因此解析问题进入raw_name和canonical_name。

公开样例：recipe3/line22/ingredient21为“小龙虾 =”，2、CUSTOM/斤；line24为“香叶 = 两片”，数量和单位为空。recipe5/line48为“黑鳕鱼，带皮，2 片，450g”，数量为空；line49为“青葱，葱白，25g。”。

上一轮对原文件连续两次复现；只在内存移除分隔等号后小龙虾名称正确，香叶中文数量仍为空；把逗号替为空格后姜数量恢复13。此对照只用于定位，不能把全局替换逗号当正式修复。

### 3.2 份数、单位和零用料

- SERVINGS仅识别阿拉伯数字＋“人”，不识别“每2份”。份/人/蛋糕尺寸/原料基准不是天然相同语义。
- MealMaterialCalculator首先检查原份数：缺少就返回UNKNOWN，即使食材数量本身明确。本轮mL→ml内存对照显示ORIGINAL_ONLY→REFERENCE_SCALED，确认大小写契约问题；单位一致后仍要求人工确认。
- kg/升等数量已转换到G/ML却保留原标签，影响消费方校验和显示。必须先统一“标准数量、标准单位、原始说明”契约，防止再乘1000或展示1000kg。
- 9道零用料为：66戚风蛋糕、68无厨师机蜂蜜面包、70烤箱版巴斯克芝士蛋糕、81龟苓膏、99酒酿醪糟、146桂林十八酿、207鱼香肉丝、258微波炉腊肠煲仔饭、277芝麻烧饼。戚风为多规格表格，其余存在计算章节无用料列表等情况。不能盲选表格一列、把工具当食材或从所有步骤无差别抽取用量。

### 3.3 本次采购未知的真实分布

现存清单有29条逐菜材料：23条scaleStatus=UNKNOWN且原因“原份数未知或无效”；4条REFERENCE_SCALED；1条区间ORIGINAL_ONLY；1条数量未标准化UNKNOWN。29条均needsConfirmation=true。因此“参考量未知”与“商品未匹配”是两件事。

确认后的需求项为25条HAVE_ENOUGH、3条NEED_BUY、1条QUANTITY_PENDING。三份报价合计87条重复来源项：75已有足量、6匹配、3城市无商品、3需求量待确认。本快照未出现UNIT_UNSUPPORTED、OUT_OF_STOCK或QUOTE_UNKNOWN，不代表这些边界不会发生。

当前Mock目录仅12个明确绑定的食材ID，全部存在，覆盖494条菜谱用料（16.33%是原料行ID覆盖率，不是采购成功率）。匹配还需要城市、数量和单位成立，广州故意无商品；修好名称不会自动补齐商品目录。UNREVIEWED本身限制可信合并，但不等于Provider必然拒绝所有已有ID。
