### R1：完整理解输出 Prompt

增加捕获实际 ModelChatRequest 的断言，验证 system/当前 payload 的结构指引确实送达网关，不仅验证替身返回固定正确 JSON；不添加第二次理解调用、修复重试或供应商特定 schema API。

### R2：严格 JSON 类型与 Bean Validation

在转换丢失原始类型前拒绝错误类型。可用本任务隔离 ObjectMapper coercion 配置或树节点验证，结合 Bean Validation 与现有 evidence/业务校验；不修改全局 MVC mapper。保留未知字段/尾随/重复键拒绝。

必须覆盖：20.9 与 "20" 不能转 Integer；数字预算不能转 String；数组数字/布尔值不能转食材名称；ID/理由类型错误；缺字段/null、超范围、伪造证据。第一阶段非法响应必须 FAILED/MODEL_INVALID_RESPONSE，检索和选择零次、成功助手/快照零条；第二阶段非法选择同样不写成功。修正现有把字符串 "1" 当合法分钟的 HTTP 夹具为 integer 1，不通过放松业务断言适配。另保留合法类型正例。

### R3：最终可见性与可信事实

选择结束之后、短事务成功提交之前，通过当前用户 RecipeReadService 公共接口再次校验每个选中 ID。可以追加最多 3 个选中 ID 的可见性检查；初始候选仍最多 5 个，不能增加检索次数或拿到新的候选。若重新读详情，重新校验最终事实、硬条件和理由一致性，不使用已经变化的事实作为可信输出。

用可控第二次模型调用屏障和临时 PG 变更候选归属/可见性（以及适合当前外键的删除/停用场景），确认不能持久化不可见候选的 SUCCEEDED/ASSISTANT/快照。安全失败按原允许错误码处理，不回传被撤权详情或 SQL 异常。不把模型调用放进事务，也不声称末次检查能彻底消除所有 TOCTOU 窗口。重放/GET 仍只读快照，查看详情仍须现有权限边界。
