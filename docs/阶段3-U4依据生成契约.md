## 1. 目标、依据与分层

选定一套餐单 → 读取并复核完整事实 → 一次指导模型调用 → 严格校验 → 保存 → 零模型回看。U3 selection 仍只保存选择，不隐式调用指导模型；未来 UF2 点击后依次提交选择和指导两个明确动作。

agent 负责新 Controller/Service/impl、证据装配和一次执行；conversation 负责动作、指导及事务；policy 负责完整 Prompt、严格 JSON、引用与安全检查。只调用 RecipeMealFactsService 公开接口，不跨模块 Mapper，不重新检索或 Embedding。

只使用所选 option 的所有菜/汤，不把另一个方案、旧聊天、其他餐或原始用户指令混入指导。每道菜输入完整 MealRecipeFacts：原材料/原行/单位/原量、全部步骤、厨具、份数/已知时间、additionalContent、来源文档/哈希/事实指纹，以及该方案完整材料参考折算和本餐确定人数/需求。不把完整事实减成摘要，不无限输入全库 Markdown。

生成前校验选中方案属于当前用户/会话/餐/版本，状态 SELECTED，事实指纹及硬资格仍满足；材料来源指纹一致。输入数据作为不可信参考，不能覆盖 system。原始材料和步骤由服务器完整展示，模型只生成解释和额外指导，不更新 recipe 或材料清单。

## 3. 模型结构与展示

System 包含完整 JSON 类型、字段、必填、枚举、长度、来源和失败边界；风格自然温和但不假装亲身经历或记住旧餐。所有对象拒绝未知/重复字段、尾随 JSON、数值自动转换及 Markdown 外壳。

模型只输出：

```text
{overview:string,
 preparation:Block[],
 recipes:[{recipeId:string, explanations:Block[]}],
 cookingOrder:Block[], cautions:Block[],
 optionalSuggestions:[{text:string,recipeIds:string[]}]}
Block = {text:string, evidence:[{recipeId:string,stepNos:int[],ingredientIds:string[]}]}
```

overview非空≤500码点，不输出新的数量/价格/营养/诊疗事实。preparation 1～20项、cookingOrder 1～30项、cautions 0～20项；recipes 恰好覆盖所选全部菜谱、无重复，每道 explanations 1～30项；Block.text 非空≤800码点、evidence 1～10项。各 evidence 只能引用所选真实ID、该菜已有stepNo/recipeIngredientId，stepNos/ingredientIds各≤50、去重，至少引用一个有效步骤或材料；不引用另一个方案。逐菜讲解的步骤引用并集须覆盖该菜全部原步骤，有材料而无步骤则引用全部材料并明确“原步骤缺失”，不能编造原做法。输出资源不够则安全失败，不能漏掉某道菜当完整成功。

optionalSuggestions≤10项，每项text非空≤500码点、recipeIds为所选子集且至少1个；服务器强制标题“模型补充：可选建议”，不自动加入材料/采购，不当原菜谱出处。

服务器生成 GuideView 的菜名、人数、材料、全部原步骤、厨具、来源和指纹，模型不能输出覆盖这些权威字段。模型文本分为“依据讲解”和“可选补充”：不得引入与所引用事实不一致的精确用量/温度/时长，不生造价格/营养值/治疗承诺；不得声明未核实整餐总耗时或偏好必然满足。实现最小关键数值一致性与危险内容校验，新增虚构克数/温度/时间反例；正则与引用存在均不能证明语义蕴含，U5仍需人工审核。

安全检查覆盖原事实、模型所有外发字段及所有历史回读；拒绝HTML/任意链接/指令注入展示/诊疗与药物建议。不可安全展示时整个指导失败，不删原材料当完整来源。生成失败只显示固定安全错误及原餐单事实，不假装成功指导。

## 4. HTTP 和兼容

新增 POST `/api/conversations/{id}/meals/{mealId}/guides`，严格请求仅 `{requestId:UUID,expectedVersion:正int32,optionId:正BIGINT字符串}`。不接 Key、用户ID、事实、提示词、模型或预算档位。

新增 GET `/api/conversations/{id}/meals/{mealId}/guides/{guideId}` 返回 GuideView，零模型/检索/凭证读取。原 `/actions/{actionId}` 仍用于动作状态/历史 MealActionView，GUIDE 动作按同一动作协议读取。

POST返回原形状 MealActionView：新同步动作终态201（FAILED亦201），同键同输入或相同已完成指导的新键200、同键在途202及Location动作URL。400参数、404不存在/越权、409版本/选择/异键在途/同键异参数、503执行关闭，原认证/CSRF/no-store不变。关闭时拒绝新GUIDE零落库/模型，终态/在途重放与已完成结果复用仍允许。

U3 MealView 保持schemaVersion=1和全部既有字段：无完成指导时guide=null/guideAvailable=false；完成后guide仅含 `{id:string,schemaVersion:1,optionId:string,version:number}` 引用，guideAvailable=true，不塞全文或用它判断供应商能力。生成期间/失败不清除选中项，meal.status仍SELECTED；GUIDE动作status单独展示。U3选择动作仍零模型，修订登记清空当前指导引用但保留历史。旧T14/聊天JSON不改。

GuideView包含schemaVersion=1、字符串id/conversationId/mealId/optionId/actionId、version、diningCount、personaVersion/promptVersion、createdAt、factsStatus、noticeCodes、完整服务器事实/材料快照及上述模型content。ID/BigDecimal字符串、未知null，原量/折算标签保留。GET在事实仍可见但变化时返回历史依据并标CHANGED；任一引用不可见返回UNAVAILABLE且content=null、recipes=[]、materials=null，隐藏所有原菜名/文本/模型建议；不泄露失权快照。动作/餐单GET同步保护guide引用和guideAvailable，不能以历史结果绕过权限。

GUIDE失败只结束GUIDE动作并保存安全错误/metrics，绝不能沿用CREATE失败清空options/selectedOptionId/将meal置FAILED。过期恢复须识别GUIDE并保留选择，所有新写可安全恢复；GET不恢复。最终成功更新验证实际行数、过期迟到结果不能成功落库。锁内纯事实核验是短读，不允许等待模型。

metrics保留modelGatewayAttempts、candidateServiceCalls=0、semanticSearchCalls=0、queryEmbeddingRequests=0、逐尝试usage未知null、durationMs；失败也记录已知用量，不把方法尝试当供应商实发或账单。不引入付费窗口或默认开启运行开关。
