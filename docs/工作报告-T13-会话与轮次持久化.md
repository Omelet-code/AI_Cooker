# T13 会话与轮次持久化工作报告

## 目标与边界

实现 T13 冻结契约中的会话元信息与历史读取，以及供后续执行层调用的内部轮次生命周期 Service。HTTP 仅开放创建会话、会话列表/详情、消息历史和轮次详情；不开放轮次提交、消息提交或流式接口。

改动限定在 `backend/src/main/java/com/cooker/conversation/**`、`backend/src/main/resources/mapper/conversation/**`、新增迁移 `V8__create_conversation_tables.sql`、对应集成测试和本报告/技术详解两份文档。保留工作树中既有 T12 与 T5 未提交内容，未改共享 API、common、identity、其他业务模块、根架构文档或依赖配置。

## 实现摘要

- V8 新建 `conversation`、`conversation_turn`、`chat_message`，使用复合外键约束会话、用户、轮次归属；唯一约束及部分唯一索引保证请求幂等、轮次编号、消息序号及单会话单活动轮次。
- `ConversationService` 通过可信 `CurrentUserService` 做用户边界过滤；列表按更新时间和 ID 倒序，消息按序号和 ID 正序，并设置私有响应 `Cache-Control: no-store`。
- `ConversationTurnService` 提供内部注册、开始、成功、失败、查询和过期恢复。写操作先锁所属会话，再锁轮次并写消息；同一 requestId 同时校验 SHA-256 和原始 USER 内容。所有数据库锁均处于本地短事务，未加入模型或网络调用。
- 注册时由 PostgreSQL `clock_timestamp()` 设置 120 秒期限；开始/成功使用数据库时钟条件更新。成功状态和 ASSISTANT 消息原子提交；过期轮次转为 `RUNTIME_INTERRUPTED`，不会补写助手消息。
- 使用显式 UUID TypeHandler，避免当前 MyBatis 版本没有内建 UUID TypeHandler 的启动错误。

## 2026-10-02 R2 复合外键专项更正

### 历史证据纠正

早先 `ConversationHttpPostgresTest` 中三条错误归属 INSERT 只断言 `RuntimeException`。独立审查通过临时 PostgreSQL 移除目标外键后确认：错误 PENDING turn 实际被 `uq_turn_one_active_per_conversation` 拒绝；两条复用既有 USER 消息 turn/role 的 message 实际被 `uq_message_turn_role` 拒绝。三个异常都是 SQLState `23505`，即唯一约束冲突。它们此前不能证明外键有效；这只确认了测试假阳性，没有发现生产外键缺失或真实越权问题。原审查输出和旧测试结果作为历史留存，不再算作外键通过证据。

### 新测试方法与断言

`ConversationCompositeForeignKeyPostgresTest` 使用两个独立 Testcontainers PostgreSQL 并各自运行 V1～V8。约束库先复现原负例的 `23505` 及确切唯一约束名。修正负例将错误 turn 设为满足 CHECK、唯一键与活动部分索引条件的 FAILED 终态；错误 message 使用无现存记录的 turn、ASSISTANT 角色和未占用 sequence。测试从 Spring `JdbcTemplate` 的异常包装中追溯 `PSQLException`，精确检查 SQLState `23503` 和三个场景对应的外键名：错误 turn 用户 `fk_turn_conversation_owner`、message 错会话 `fk_message_turn_owner`、message 错用户 `fk_message_turn_owner`。

失败后比较用户/会话/turn/message 行数及关键原记录，确认无非法行且没有误改；并成功插入合法 SUCCEEDED turn 与 USER/ASSISTANT 消息。隔离对照库仅删除两个目标复合外键，保留其他 CHECK、用户 FK、唯一约束和部分唯一索引，重复三个修正后的错误归属组合均成功插入。这证明负例确实依赖目标 FK。约束移除仅发生在专用临时容器，测试结束由 Testcontainers 销毁；生产迁移和开发库未更改。
