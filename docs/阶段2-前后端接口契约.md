# 阶段 2 前后端接口契约

> 契约版本：s2-api-v1；架构冻结于2026-09-30，状态更新于2026-10-02。各实现切片、开发V7部署及T11均已验收；用户明确确认剩余浏览器5项全部通过。下述Cookie偏差按ADR-007保留，不修复；字段与接口契约不变。阶段二签收不扩展为阶段三实现、收费调用或提交合并授权。

> 最新用户接受的例外：COOKER_ACCESS在未勾选时仍Max-Age=900，用户明确决定暂不修复；COOKER_REFRESH未勾选时仍为会话Cookie。此取舍不代表旧偏差已修复，也不延长JWT或续期绝对期限。详情见ADR-007；此前要求两枚Cookie均非持久的说明由此覆盖。

## 1. 范围和共同约定

阶段 2 在浏览器完成注册、登录、记住我、真实菜谱列表/详情、收藏、完成烹饪、做菜历史和评分展示。页面最终调用 Spring Boot 和 PostgreSQL；固定 Mock 只用于接口未就绪时的开发与单元测试。阶段验收使用 real 模式，不调用 LLM 或 Embedding。

- API 根路径为 `/api`，以下列出的路径均含该前缀。前端只请求相对路径，不在页面里拼接后端域名。
- JSON 字段为 camelCase；所有数据库 ID 在 JSON 和 URL 中均使用十进制字符串，避免 Java `BIGINT` 超出 JavaScript 安全整数范围。页码、次数、评分使用整数；原料 `numeric` 数量使用十进制字符串或 `null`。
- 时间使用带时区的 ISO 8601 字符串；服务端以 UTC 返回，前端转换显示。未知值返回 `null`，数组无内容返回 `[]`，不能把未知时间、评分和数量转换为 0。
- 所有阶段 2 菜谱列表、详情、收藏和做菜接口要求登录。系统公开菜谱和当前用户自己的私有菜谱可见；本阶段不创建私有菜谱。不存在或不可见的资源统一返回 404。
- 请求中不包含 `userId`。当前用户只能来自服务端验证过的 JWT 身份；非法字段不得成为授权或所有者依据。
- 成功响应统一为 `{ "code": "OK", "message": "成功", "data": ... }`。正常读取和幂等写入使用 HTTP 200；注册及首次完成烹饪使用 HTTP 201；幂等重放完成事件使用 HTTP 200。
- 错误响应为 `{ "code": "机器错误码", "message": "中文提示", "data": null }`。参数错误可追加 `fieldErrors: [{ "field": "字段名", "message": "中文提示" }]`。安全过滤器、Controller 和业务异常遵循同一错误结构；不能所有错误都返回 HTTP 200。
- 分页统一 `page=1`、`size=20`，size 上限 50；越界或非法参数返回 400。响应为 `{ "items": [], "page": 1, "size": 20, "total": 0 }`。空页正常返回空 items；total 是符合条件的记录总数。
- 敏感响应及个人数据采用 `Cache-Control: no-store`。请求体不整体写日志；密码、认证令牌、续期令牌和 API Key 不出现在业务响应体或异常中。

## 2. 认证、CSRF 与记住我（T7 / F2-A）

| 方法和路径 | 请求 | 成功 data | 语义 |
|---|---|---|---|
| `GET /api/auth/csrf` | 无 | `{ token: string, headerName: "X-XSRF-TOKEN" }` | 未登录可调用，初始化 CSRF；token 只保留在页面内存 |
| `POST /api/auth/register` | `{ username: string, password: string }` | `UserProfile` | 创建用户，不自动登录；成功后转登录页面 |
| `POST /api/auth/login` | `{ username: string, password: string, rememberMe: boolean }` | `UserProfile` | 设置认证 Cookie；rememberMe 默认为 false |
| `GET /api/users/me` | 无 | `UserProfile` | 验证访问 JWT、取得用户信息 |
| `POST /api/auth/refresh` | 空对象 `{}` | `UserProfile` | 校验续期 Cookie，原子轮换并设置新 Cookie |
| `POST /api/auth/logout` | 空对象 `{}` | `null` | 撤销当前登录的续期凭证并清 Cookie；重复退出允许成功 |

`UserProfile = { id: string, username: string }`。首版用户名 3～32 位，只含英文字母、数字、下划线；输入去首尾空白，以小写统一存储和比较。密码 12～128 字符，不 trim、不截断，不强制无意义的字符组合规则。错误的用户名或密码统一提示“用户名或密码错误”。密码采用 Argon2id 强哈希；通过 Spring Security 实现，不自研哈希算法，新增依赖和参数在 T7 开始时核验 Boot 管理版本兼容性。

访问JWT默认15分钟，访问Cookie现有实现持久保存相同时间（含未勾选，用户已接受）。续期凭证勾选时最长30天、未勾选时最长24小时；前者使用持久续期Cookie，后者使用非持久续期Cookie。浏览器会话恢复可能保留会话Cookie，故不承诺关闭浏览器必然注销。期限为本次登录绝对期限，轮换不无限延长；默认时长仍可配置。

认证 Cookie 使用项目独立名称 `COOKER_ACCESS`、`COOKER_REFRESH`，HttpOnly=true；访问 Cookie Path=`/api`，续期 Cookie Path=`/api/auth`，不设置 Domain。生产使用 HTTPS、Secure=true、SameSite=Lax；本地 localhost 开发配置 Secure=false。CSRF Cookie 与认证 Cookie 是不同对象，具体名称和请求处理配置由 T7 对照 Spring Security 版本实现并测试；前端通过 csrf 接口取得可提交的 token，无需读取认证 Cookie。

注册、登录、续期、退出、收藏、完成烹饪和 Key 修改均要求 `X-XSRF-TOKEN`。登录、退出后重新获取 CSRF；其余遇到明确的 `CSRF_INVALID` 可重新获取一次并重试一次。`/auth/*` 的登录、续期、退出不能被过期的访问 JWT 提前阻断；续期依靠自己的续期凭证校验，不依赖访问 JWT 仍有效。

前端启动流程：先初始化 CSRF，再请求 me；me 返回 401 时尝试一次 refresh；续期成功后加载用户数据，失败后显示登录页。受保护请求返回 401 时，共享请求层在同一页面内合并并发 refresh，再最多重放一次原请求。登录/注册失败不触发自动 refresh；refresh 本身不能递归刷新。浏览器关闭再打开时，通过续期 Cookie 恢复登录，无需前端保存密码或 JWT。

续期轮换使用数据库事务。旧续期凭证不能再次成功换取新凭证；并发竞争的失败响应不得清除另一请求刚写入的有效新 Cookie。前端不无限重试跨标签页竞争；如收到 `REFRESH_CONFLICT`，尝试一次 me 检查共享 Cookie 是否已被另一标签页更新，否则提示重新登录。多标签页竞争必须在 T7 报告中说明验证结果。

退出当前浏览器后不得再成功续期；已签发的访问 JWT 在最长剩余 15 分钟内可能仍有效，此版本不承诺全设备立即撤销。前端退出时清除用户 Store、列表、评分和未完成操作状态，并获取新的 CSRF。

## 3. 真实菜谱读取与收藏（T9 / F2-B）

| 方法和路径 | 请求 | 成功 data |
|---|---|---|
| `GET /api/recipes` | `page`、`size`；可选 `keyword`，最多 100 字符 | `Page<RecipeCard>` |
| `GET /api/recipes/{id}` | 菜谱 ID | `RecipeDetail` |
| `POST /api/recipes/{id}/favorites` | 空对象 `{}` | `{ recipeId: string, isFavorite: true }` |
| `DELETE /api/recipes/{id}/favorites` | 无 body | `{ recipeId: string, isFavorite: false }` |
| `GET /api/favorites/recipes` | `page`、`size` | `Page<RecipeCard>` |

列表 keyword 只做菜名包含匹配，并转义 SQL LIKE 通配符；列表按 recipeId 升序，收藏按收藏时间降序、recipeId 降序。它是普通菜谱浏览入口，不调用 T5 混合检索或生成查询向量。数据来自已导入的菜谱表，不硬编码真实 ID 或假造缺失字段。

共享类型：

```text
RecipeCard {
  id: string, name: string, categoryCode: string,
  summary: string | null, difficulty: number | null,
  estimatedMinutes: number | null, isFavorite: boolean
}
RecipeDetail {
  recipe: RecipeCard,
  servings: number | null,
  ingredients: IngredientView[], steps: StepView[], tools: ToolView[],
  additionalContent: string | null
}
IngredientView {
  name: string, rawLine: string,
  amountMin: string | null, amountMax: string | null,
  unitLabel: string | null, optional: boolean
}
StepView { stepNo: number, content: string }
ToolView { name: string, optional: boolean }
```

ingredients 按 sortOrder、steps 按 stepNo、tools 按稳定名称和 ID 排序。原始文字保留用于展示“不明用量”，name 优先标准名称，不能匹配时使用 rawName。阶段 2 的正文使用 Vue 文本插值展示，保留必要换行，不使用 `v-html` 或把 Markdown 当 HTML 执行。没有图片的菜谱使用普通文字卡片。

收藏添加和删除均幂等；添加已收藏、移除未收藏均成功。删除收藏不删除做菜记录。两项写操作成功后重新读取对应列表或更新局部状态，失败不伪装成功。

## 4. 完成烹饪与做菜历史（T10 / F2-C）

| 方法和路径 | 请求 | 成功 data |
|---|---|---|
| `POST /api/cooking-records` | `{ recipeId: string, idempotencyKey: string, rating: number | null }` | `CookingRecord` |
| `GET /api/users/me/cooked-recipes` | `page`、`size` | `Page<CookedRecipeCard>` |

```text
CookingRecord {
  id: string, recipeId: string, cookedAt: string, rating: number | null
}
CookedRecipeCard {
  recipe: RecipeCard, cookCount: number, lastCookedAt: string,
  familiarityCode: "FIRST_TRY" | "FAMILIAR" | "FREQUENT",
  familiarityLabel: "初尝" | "熟悉" | "常做",
  latestRating: number | null
}
```

前端在用户明确确认“这次做完了”时生成 UUID 幂等键，并在本次操作成功或显式结束前保留该键。重复点击、网络超时后的重试、认证续期后的请求重放均复用同键和同一内容。以后再做同一道菜生成新键。按钮在提交中禁用；网络不明结果不能提示“已失败”后自动换新键再次提交。

服务端使用 `(user_id, idempotency_key)` 唯一约束，并在事务内处理并发重复请求。同键同内容返回原 CookingRecord；同键不同 recipeId 或 rating 返回 409 `IDEMPOTENCY_CONFLICT`，不新增记录。cookedAt 由服务端记录本次提交时间，不开放客户端任意修改。响应返回稳定事件，不嵌入会随以后烹饪变化的累计统计。

评分允许 null 或整数 1～5；首版随完成事件一起提交，编辑既有记录/评分后置。做菜历史按 lastCookedAt 降序、recipeId 降序，一道菜一张汇总卡；cookCount 是所有完成事件数，latestRating 是按 cookedAt 和 recordId 确定的最近一次非空评分。1～2 次 FIRST_TRY，3～5 次 FAMILIAR，6 次起 FREQUENT。未评分显示“未评分”，不展示 0 星。

## 5. DeepSeek Key（T8；前端设置页后置）

- `PUT /api/users/me/llm-credential`：请求 `{ apiKey: string }`；data `{ configured: true }`。校验非空且长度最多 4096 字符，不发送真实平台验证请求。
- `DELETE /api/users/me/llm-credential`：data `{ configured: false }`，重复删除成功。
- `GET /api/users/me/llm-credential/status`：data `{ configured: boolean }`。

数据库保存认证加密密文、随机 IV、算法/密钥版本；主密钥从 `LLM_CREDENTIAL_MASTER_KEY` 注入。接口永不返回 Key、尾号或密文。T8 在阶段 2 通过接口及数据库测试验收，模型 Key 页面在 Agent 阶段接入。

## 6. 错误码与前端动作

| HTTP | code | 页面动作 |
|---|---|---|
| 400 | VALIDATION_ERROR | 展示中文字段或参数错误 |
| 401 | AUTH_REQUIRED / ACCESS_TOKEN_EXPIRED | 受保护请求可尝试一次续期；仍失败回登录页 |
| 401 | LOGIN_FAILED | 展示统一用户名/密码错误，不续期 |
| 401 | REFRESH_REJECTED | 清用户状态，回登录页，不循环刷新 |
| 403 | CSRF_INVALID | 获取 CSRF 后最多重试一次；不得当登录过期 |
| 403 | ACCESS_DENIED | 展示无权操作，不自动续期 |
| 404 | RECIPE_NOT_FOUND | 不存在或不可见菜谱；展示不可用状态 |
| 409 | USERNAME_TAKEN | 注册提示用户名已使用 |
| 409 | IDEMPOTENCY_CONFLICT | 保留本次事件，提示冲突，不自动换键重试 |
| 409 | REFRESH_CONFLICT | 按认证流程检查另一标签页已更新的 Cookie |
| 500 | INTERNAL_ERROR | 通用中文错误；不能回传堆栈、SQL、凭证 |

HTTP 请求层设置可配置超时，默认 10 秒；超时和网络错误使用前端本地错误状态，不冒充服务端 code。请求层不自动重试未知结果的写操作，用户重试完成烹饪必须复用幂等键。

## 7. 前端路由与状态

| 路由 | 页面 | 所属模块 |
|---|---|---|
| `/login` | 用户名、密码、记住我、注册入口 | identity |
| `/register` | 注册表单与登录入口 | identity |
| `/recipes` | 真实菜谱分页列表，菜名筛选 | recipe |
| `/recipes/:id` | 原料、步骤、厨具、收藏及完成烹饪弹窗 | recipe |
| `/favorites` | 当前用户收藏列表 | recipe |
| `/cooked-recipes` | 当前用户做过的菜谱、次数和评分 | recipe |

`/` 重定向到 `/recipes`。Pinia 的用户 Store 只保留用户资料和认证加载状态，不保存认证令牌；刷新页面时重新验证。共享 fetch 请求层集中处理 credentials、CSRF、超时与有限续期，模块 API 不重复实现。路由守卫等待身份初始化完成；登录后的跳转只允许站内路径，避免开放跳转。列表具备加载、空数据、错误、分页与权限失效状态；详情在提交中显示明确状态。

API 模式为 `real` 或 `mock`，默认 `real`；mock 必须显式开启并在页面显示“开发 Mock”。Mock 只实现本契约，不改字段；真实模式不得静默回退 Mock。使用浏览器原生 fetch，不新增 Axios 或另一套状态管理；简洁原生组件与 CSS 足以完成最小页面。

## 8. 本地与部署衔接

开发通过 `http://localhost:5173` 的 Vite `/api` 代理访问后端 `localhost:8080`；浏览器只面对前端同源，保留 `/api` 路径，不另开跨域 Cookie 流程。数据库连接从配置注入，实施时先核对真实 PostgreSQL 端口，不能把本机某个端口硬编码。

生产继续使用 Nginx 静态站点和 `/api` 反向代理，发布时配 HTTPS 与 Secure Cookie。阶段 2 浏览器验收在本地 real 模式执行；Linux/生产部署由后续阶段验收。
