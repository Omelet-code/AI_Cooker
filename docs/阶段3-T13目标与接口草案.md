## 1. 目标与学习重点

保存用户会话、消息和一次请求对应的执行轮次，使刷新回读、跨用户隔离、请求重放与并发冲突可以验收。T13负责业务状态与短事务，T14才连接模型和真实检索，不能把测试桩回复当作已完成RAG。

与熟悉的Spring Boot业务相同：Controller接收请求，项目Service维护规则，Mapper执行SQL。新增知识主要是数据库唯一约束下的幂等、原子状态转换、有限历史与外部调用不放在数据库事务中。

- 创建和查询会话、查询消息/轮次是本切片的真实持久化功能；模型执行接口先以项目Service端口隔离，测试桩只能在测试中使用。

## 3. 推荐接口方向（待冻结）

- `POST /api/conversations`：创建当前用户会话，不调用模型。
- `GET /api/conversations`：当前用户分页列表。
- `GET /api/conversations/{id}`：会话元信息。
- `GET /api/conversations/{id}/messages`：分页历史，稳定顺序。
- `POST /api/conversations/{id}/turns`：待T13/T14切分时明确开放时间，输入requestId/content；接受一次轮次不代表模型已完成。
- `GET /api/conversations/{id}/turns/{turnId}`：权威状态回读。

复用s2-api-v1的成功/错误envelope、字符串ID、UTC时间、分页、Cookie/CSRF、no-store；不接收userId。越权与不存在均404。同键同内容回读原轮次，不重新执行；同键异内容409。终态回读和任何GET不启动模型。SSE及事件字段留T15。

## 4. 数据与验收方向

推荐conversation、conversation_turn、chat_message三表；归属/状态/顺序为关系列，可变且已经校验的结果快照可用JSONB，不能存Key、完整Prompt或思考正文。原始用户消息属于用户业务历史，与运行日志不同。

会话归属校验与写入应在同一短事务中。并发轮次的互斥、幂等唯一键、状态转换CAS、遗留运行轮次中断策略和恢复期限须在派发前冻结；不能凭本地锁声称跨进程保证，不自动重放可能已计费的请求。

验收至少覆盖A/B隔离、同键并发/异内容、消息顺序和分页、非法参数、无执行器时不伪造结果、重启/失联后的明确状态；隔离Testcontainers运行迁移和SQL，常规测试零真实模型请求。部署至开发PG和浏览器联调需明确部署范围，不能从非收费自动化授权推导出可迁移用户开发库。

本草案不冻结最终字段、状态机、消息长度、HTTP状态及执行上下文方式；具体任务卡必须补齐后才能派发。
