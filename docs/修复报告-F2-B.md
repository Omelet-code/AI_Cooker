## R2：收藏写入与旧查询协调

`RecipeStore` 在成功收藏写入后先依据服务端响应更新当前列表、收藏缓存和详情；再对已加载或仍在进行中的列表、收藏和详情视图发起受控重读。重读会分配新的各自请求序号，因此旧请求的响应、错误及 `finally` 都不能覆盖新数据或提前清除新请求的 loading 状态。该方案使用现有 Pinia Store 与请求序号，没有引入新状态框架。

取消收藏时立即从当前收藏页移除，并按已知收藏事实修正总数；重读若发现当前页大于新总数计算出的末页，会自动请求有效页。重读错误由原 Store 错误字段承接，最新请求的 `finally` 正常结束 loading；收藏写入失败仍返回失败并显示错误，不做成功态变更。

`recipe-store.test.ts` 使用实际 Pinia Store、可控 Promise 与 mock API 覆盖：

- 添加成功后，旧列表、收藏、详情查询晚到，以及跨视图受控重读；
- 取消最后一页条目后旧收藏查询晚到、总数变化、超界页回退；
- 收藏写成功但随后重读失败时 loading 结束，旧响应仍不能覆盖收藏状态；
- 收藏写入失败不伪装成功，以及同用户快速搜索、账号切换和旧用户响应清理。
