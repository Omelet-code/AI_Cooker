### 内部契约与安全约束

1. 通过项目 Service 处理一次模型请求；实现放 `service.impl`，不能把 `ChatModel`、供应商响应或明文 Key 直接作为后续 Controller 的接口。DTO 至少承载有限消息、文本/JSON 输出模式；结果包含内容、结束原因和可空 usage，后续工具消息适配不开放工具执行能力。
2. 每次业务调用只发起一次供应商请求，不自行循环、修复 JSON、重试或访问检索。JSON 模式要求提示词包含 JSON 输出要求；校验 JSON 语法，具体菜谱约束 DTO 的校验留 T14。空内容、无 choices、畸形 JSON 和截断输出均安全失败；usage 缺失为未知，不能记成 0。
3. 使用当前已认证用户的 T8 Service 解密凭证并创建本次手工客户端。没有全局模型 Key，不缓存跨请求明文 Key，不通过修改共享客户端字段换用户。至少验证两用户交错及并发请求，不能只测先 A 后 B。
4. 本任务同步执行；不创建异步任务或自行传递 SecurityContext。未来异步编排必须另行冻结可信上下文；不提供任意 userId 解密入口。
5. 运行目的地址固定为 `https://api.deepseek.com`，路径 `/chat/completions`，模型显式 `deepseek-flash`。非思考为本切片推荐基线：显式 `thinking.type=disabled`，不发送相冲突的 `reasoning_effort`。不使用 Beta strict，不暴露可由用户指定的 URL 或模型。
6. Mock Server 地址只允许测试显式注入，普通应用配置不得接受任意外部地址携带用户 Key。无凭证时普通应用仍能启动；实际网关调用才报凭证缺失。
7. 建议连接超时 5 秒、响应超时 30 秒、最大输出 2048 tokens。单次最多 16 条消息、总内容最多 20000 Unicode 码点；超限直接拒绝，不在网关悄悄删历史。它们是初始资源限额，不是精确 token 预算或真实性能承诺。
8. 显式关闭供应商自动重试，并在故障测试中断言 Mock Server 请求数恰好为 1；非法输入、未登录、凭证缺失或解密失败时为 0。不得通过生产环境变量开启真实模型测试，也不得触发既有收费检索评测。
9. 不记录 Prompt、options、API Key、Authorization、原始供应商响应/异常链或 reasoning_content。覆盖 ADR-008 所述框架空响应 WARN 分支，采用明确日志抑制及安全异常转换；保留无内容的分类、耗时、调用次数等必要诊断。
10. String 形式的 Key 无法保证即时擦除堆内存；教学文档如实解释减少生命周期与引用的措施，不宣称“完全消除内存中的密钥”。

错误分类使用项目内部安全异常，至少区分：输入非法、未配置凭证、凭证服务不可用、模型鉴权失败、限流、供应商不可用、超时及响应非法。供应商 401 **不是** Cooker 登录失效；不能映射为让前端退出登录的 `AUTH_REQUIRED`。本任务无模型 HTTP 入口，对外 HTTP/code 的最终映射留调用入口切片冻结。

### 复用接口契约（不新增后端 API）

| 接口 | 请求 | 成功 data |
|---|---|---|
| `GET /api/users/me/llm-credential/status` | 无 | `{ configured: boolean }` |
| `PUT /api/users/me/llm-credential` | `{ apiKey: string }` | `{ configured: true }` |
| `DELETE /api/users/me/llm-credential` | 无 | `{ configured: false }` |

统一成功 envelope 为 `{ code: "OK", message: "成功", data: ... }`，三接口成功 HTTP 200。页面调用 `apiClient.request` 时路径不重复加 `/api`；复用 Cookie、CSRF、一次身份续期与统一错误处理，不另写直连供应商 fetch。

后端校验非空白、最多 4096 Unicode 码点；不强制 `sk-` 前缀，不 trim 或改变用户 Key。实际接口只返回 configured，不返回尾号、密文或完整 Key。主密钥缺失/不可用当前为 HTTP 500、`INTERNAL_ERROR`、中文“凭证服务暂不可用”，不虚构独立新错误码。

### 页面行为与验收

1. 状态为加载中、已配置、未配置或读取失败；读取失败不能显示为未配置。明确提示“已保存不等于已验证有效”，不提供未实现的“验证 Key”按钮。
2. 输入采用密码型控件，不预填已有 Key、不读回、不放入持久 Store、Web Storage、URL 或日志；提示用户不要把 Key 发到聊天里。自动填充尽量关闭，但不承诺浏览器一定遵守。
3. 保存成功后清空输入；删除前确认，成功后状态为未配置并清空输入。离开页面、退出或切换身份清除本页输入和状态；旧账号迟到响应不得覆盖新账号页面。
4. 防重复提交，状态请求与写请求不得互相用旧结果覆盖。失败不假报成功；网络/超时导致结果未知时允许回读状态，但 configured 只能证明存在凭证，不能证明新 Key 已替换。恢复后可由用户明确重试保存/删除，不静默重发写请求。
5. 401 依赖现有共享层，最终失效按原身份路径处理；400、403、500、网络、超时和异常响应均显示安全中文反馈，不回显请求体或完整输入。
6. 默认 real；测试用虚构材料和 Mock 响应，不将 Mock 结果当真实后端验收。开发显式 mock 模式不得静默调用真实接口或显示真实成功。
