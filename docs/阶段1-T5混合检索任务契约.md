# T5：菜谱混合检索任务契约

> 状态：用户于 2026-09-27 明确授权 T5；实现已验收并合并；T6 仍须单独授权
>
> 基线：`main` 已合并 T1～T4；固定 HowToCook 快照含 372 道菜谱、1850 个检索块。

## 1. 任务目标

实现后端 `RecipeSearchService.search(RecipeSearchCriteria)`。输入自然语言查询和阶段 1 的结构化条件，返回数据库中真实存在、用户有权查看的菜谱候选及可解释的命中原因。T5 只建立检索 Service 契约，不接入 Agent、前端或用户登录流程。

本任务由一个独立实现会话完成；主架构会话负责冻结契约、讲解技术、审查代码和验收结果。

## 2. 输入和既有依赖

- 事实数据由 `recipe` 模块拥有；`retrieval` 只能调用该模块的公开 Service/DTO，不能引用其 Mapper、Entity 或 XML。
- `recipe_search_document` 已保存 `overview`、`ingredients`、`tools`、`steps` 检索块；`tsv` 是 `zhparser` 生成的中文全文索引，`embedding` 为 `text-embedding-v4` 的 1024 维 document 向量。
- 查询文本需要用同一模型、同一维度，以 `text_type=query` 生成临时向量。查询向量不写入菜谱表。
- `RecipeSearchCriteria` 包含 `query`、`limit`、`categoryCodes`、`maxCookingMinutes`、`includeUnknownCookingTime`、`availableToolNames`、`excludedIngredientNames`、`viewerUserId`。查询去空白后不能为空；`limit` 默认 10、最大 20。
- 预算、库存覆盖率、健康判断和用户意图抽取属于后续阶段，不进入 T5 排序规则。

## 3. 检索顺序与边界

1. `recipe` 模块提供只读的菜谱资格筛选能力：按分类、已知/未知烹饪时间、必需厨具和排除食材筛出候选 ID，同时处理规范食材名与别名，并按当前事实数据核对可见性。时间未知时只有 `includeUnknownCookingTime=true` 才可保留；传入空的可用厨具集合表示没有厨具。
2. `retrieval` 查询自身的投影表时再次校验 `source_type`、`owner_user_id`、`visibility`、`embedding_status=READY`、模型、维度、模板版本。系统公开菜谱可见；用户私有菜谱仅所有者可见。结构化过滤和权限过滤必须在两路 Top 30 截断之前生效。
3. 词法通道以菜名/规范食材/别名精确命中为优先级，再使用现有 `tsv` 中文全文检索；`pg_trgm` 用于菜名模糊补充。不得引用旧草案中不存在的 `lexical_text` 列。需要新增扩展或索引时只追加 Flyway V3，不能修改已应用的 V1/V2。
4. 向量通道对非空且版本一致的向量按 cosine distance 从小到大排序，精确扫描即可；不引入 HNSW。百炼查询失败或缺少查询 Key 时，已就绪文档仍可走词法通道；失败状态的检索块不参与任一通道。
5. 每路先按 `recipeId` 保留最佳块，再各取前 30 道菜谱。同一道菜的多个步骤块不能累计加分。以 `1/(60+lexicalRank)+1/(60+vectorRank)` 做 RRF，缺席通道不计分；同分时按词法优先级、词法分数、`recipeId` 稳定排序。
6. 返回 `recipeId`、最终排名、两路名次、RRF 分数、命中原料与原因码。只能使用检索事实生成原因码，不让模型编造解释。

## 4. T4 必要修正

索引重建的“未变化”判定还需比较 `sourceDocumentId`、`sourceType`、`ownerUserId` 和 `visibility`。元数据变化必须更新检索投影；可以复用未变的向量，避免重复付费，但不得让旧权限信息留在可查询索引中。测试至少覆盖公开改私有及所有者变化。此修正纳入本次用户认可的 T5 实现范围。

## 7. 学习提示

- `tsvector/tsquery`：类似 MySQL 全文检索的“索引文本/查询表达式”，这里由 `zhparser` 处理中文；它解决词面命中。
- `pg_trgm`：按字符片段比较短名称，用于拼写或近似菜名；它不替代语义检索。
- `pgvector <=>`：计算余弦距离，数值越小越接近；它解决表达不同但含义接近的问题。
- `RRF`：只合并两路名次，不直接相加不同量纲的分数。
- `Flyway`：像数据库结构的版本控制；已应用的 V1/V2 不能回改。
- `Fake Provider`：测试中用可预测的向量替代收费服务，把排序正确性和模型质量分开验证。
