# D2-B1 技术文档：厨房启用配置

日期：2026-10-10。仅部署配置与静默验证；默认关闭，显式开启路径已准备，当前没有运行服务或验证真实模型。

## 真实配置链

| 配置 | 默认/注入 | 实际消费路径 |
|---|---|---|
| COOKER_AGENT_EXECUTION_ENABLED | `${COOKER_AGENT_EXECUTION_ENABLED:-false}` | Spring环境覆盖 `cooker.agent.execution-enabled`；MealPlanningServiceImpl、MealGuidanceServiceImpl等读取既有@Value |
| DASHSCOPE_API_KEY | `${DASHSCOPE_API_KEY:-}` | application.yml的retrieval.index.api-key → RetrievalIndexProperties → QueryEmbeddingServiceImpl |
| COOKER_RETRIEVAL_INDEX_ENABLED | 固定false | document索引配置开关，且没有recipe-index profile |
| COOKER_RECIPE_IMPORT_ENABLED | 固定false | 初始化导入仍关闭，无recipe-import profile |
| COOKER_EVALUATION_HTTP_ENABLED | 固定false | 不开放评测HTTP或恢复旧有限批次 |
| SPRING_PROFILES_ACTIVE | docker | 普通应用，不自动生成document向量 |

QueryEmbeddingServiceImpl的query通道只检查api-key是否非空，不依赖document enabled=true；因此可开启用户语义查询而保持document任务关闭。索引runner另有recipe-index profile和enabled双条件。没有发现还需新增业务开关的阻断，无需改application.yml或客户端源码。

ModelGatewayServiceImpl调用当前用户LlmCredentialService解密凭证，DefaultDeepSeekChatClientFactory固定 `https://api.deepseek.com`、`deepseek-flash`，沿用无重试/有界调用。LLM Key由各用户网页账户设置，AES-GCM机制不变；平台百炼Key由运维运行时注入，供多人query使用，不提供服务端共享DeepSeek Key。

## 静默验证与秘密边界

缺失厨房开关按false，显式值仅接受小写true/false，空值、大小写变体、yes/1和注入均拒绝。true时Key须符合 `sk-[A-Za-z0-9_-]{20,200}`，拒绝明显change/placeholder/replace/your/example/fake/dummy/test占位及单字符重复。关闭允许空Key。该规则只是本地形状筛选，不请求供应商，不证明账户/余额/地域或真实Key有效。

render只读显式env，不搜索开发env。通用错误不输出值、异常正文或Docker完整渲染，Compose调用config --quiet。Compose的shell变量优先级可能覆盖env文件，因此对子进程明确设置本次已校验值与安全默认，也覆盖原限流默认，防止shell残留true或Key导致默认配置意外开启。继承环境里的厨房Key被排除，不读取其值。测试仅使用假Key。

镜像不需要重建：修改的是容器运行环境，后端Dockerfile只复制jar，无ARG/ENV秘密；白名单装配和dockerignore继续排除真实env、证书与缓存。真实Key保存在发布包外的受限配置/Secret；运行环境注入不等于容器inspect对运维不可见，不能打印inspect环境或完整Compose配置。没有把真实Key写入本轮源码、报告或镜像。

## 启用与禁用

操作模板见部署手册D2-B1节。用户在服务器受限env设置true与百炼Key，静默检查；已有部署先停新增厨房流量并核对在途，再仅对批准项目backend执行 `up -d --no-deps --force-recreate backend`，避免仅restart沿用旧环境。评测/导入/document开关、Nginx429/并发、Secure Cookie/CSRF、JVM/Hikari/4GB与PG/Web边界保持。

紧急禁用先停新流量/核对在途，设false并清空百炼Key，静默检查后受控重建同一backend，不删卷/用户凭证，不替换加密主密钥。已经发给供应商的请求不保证立即终止或停止计费。本轮不执行这些真实动作。

用户2026-10-10允许本次演示厨房调用并自愿承担费用，覆盖以前累计配额缺口必须禁用的策略；默认安全关闭依然保留。累计费用配额尚未实现，公共Embedding Key可能由多个用户消耗，入口并发无法限制202后的后台任务，也不是费用硬上限。无新增计费系统，无旧GLOBAL_STOP恢复，执行者仍不收费回归。
