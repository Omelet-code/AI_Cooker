## 2. 实现和选择

实现三个契约端点：PUT 保存/覆盖当前用户 Key，DELETE 删除且重复删除成功，GET status 只返回 `configured`。所有响应只含统一封装的状态，不输出 Key、尾号、密文、IV 或版本，并设置 `Cache-Control: no-store`。HTTP 身份只从 `CurrentUserService.requireUserId()` 取得；Mapper 查询和写入均按该用户。内部 `decryptCurrentUserCredential()` 只使用当前 SecurityContext，没有任意用户明文读取接口，也没有 HTTP 解密端点。

加密采用 JDK JCA `AES/GCM/NoPadding`、256 位主密钥、每次新生成 12 字节 `SecureRandom` IV 和 128 位认证标签。AAD 使用稳定二进制格式绑定用途、用户 ID、算法版本和密钥版本。算法版本与密钥版本独立保存，当前仅接受版本 1，未知版本拒绝。数据库保存密文（包括认证标签）、IV、两个版本和时间；不存 Key 尾号。V7 每用户唯一一行，用户外键级联删除，IV 长度、密文最小长度与正版本有数据库约束。

主密钥仅从 `LLM_CREDENTIAL_MASTER_KEY` Base64 注入，惰性校验为恰好 32 字节；启动不读取或验证它，因此主密钥缺失不会阻断登录、菜谱、状态和删除。保存和解密缺少/错误主密钥时安全失败且不写明文、不带底层异常；状态/删除不依赖密钥。覆盖使用 PostgreSQL `ON CONFLICT(user_id) DO UPDATE`，在 Spring Service 事务内更新材料和 `updated_at`。DTO 保留 Jackson 3 原始 JSON 节点类型，避免数值被强制转换为字符串；只接受非空字符串、最多 4096 个 Unicode 码点。DTO、Entity 和加密值对象的 `toString` 均脱敏。

## 5. 未完成项与风险

- 没有实现前端设置页、Agent 调用、真实模型请求或平台 Key 有效性检测，均在当前任务范围外。
- 当前只支持 `algorithm_version=1`、`key_version=1`。轮换主密钥前须保留旧密钥，设计双版本读取/新版本写入、可回滚的重加密迁移及完成率验证；直接替换会令旧密文无法解密。本实现未声称支持热轮换。
- 主密钥缺失、格式错误、认证标签失败或版本不支持，对凭证加密/解密统一返回通用 `500 INTERNAL_ERROR`；底层异常不保留为 cause。应用能启动，状态/删除仍工作。上线运行仍须由部署环境提供稳定 Secret，否则当前用户不能保存或读取已有凭证。
- Java `byte[]` 在操作完成后尽力清零；JVM 不保证 `String` 明文可擦除。应用进程和主密钥同时失陷仍可暴露明文，需要以部署 Secret 管理、最小日志和进程权限降低风险。
- 尚无真实浏览器设置页或 Agent 端到端联调；本任务只证明后端 HTTP、隔离 PostgreSQL 和单元行为。
