# T13 会话与轮次契约

日期：2026-10-02。版本：`s3-conversation-v1`。状态：主架构冻结，用户在T13下一步说明后回复“继续推进吧”，允许本切片交给原后端实现。冻结不等于接口已实现或部署。

## 1. 边界与职责

T13提供真实会话元信息与历史读取，以及供未来编排调用的轮次持久化Service。T14才连接模型、检索与消息执行入口；T15再做异步/SSE。T13不调用T12、DeepSeek或百炼，不在生产环境提供假助手回复。

- `ConversationService`：创建/分页/详情/消息读取，可信身份来自CurrentUserService。
- `ConversationTurnService`：注册、开始、完成、失败、状态读取、过期恢复；只依赖本模块Mapper与身份Service，不反向依赖agent。
- Controller只开放下方明确列出的接口，不将内部状态变更暴露为客户端可调用HTTP。
- 所有业务方法均做自身输入与权限校验；不能仅靠Controller的Bean Validation保证跨模块调用安全。

## 2. 已冻结HTTP接口

复用s2-api-v1的Cookie/CSRF、`ApiResponse`、字符串ID、UTC ISO8601、分页与no-store。请求不得以userId指定所有者。ID须为合法正BIGINT十进制字符串，超范围/非法参数400；有效ID不存在或越权404。

| 方法/路径 | 输入 | 成功HTTP/data |
|---|---|---|
| POST `/api/conversations` | `{ title?: string }` | 201 / ConversationView |
| GET `/api/conversations` | page=1,size=20，上限50 | 200 / Page<ConversationView> |
| GET `/api/conversations/{id}` | ID | 200 / ConversationView |
| GET `/api/conversations/{id}/messages` | page=1,size=20，上限50 | 200 / Page<ChatMessageView> |
| GET `/api/conversations/{id}/turns/{turnId}` | 两个ID | 200 / TurnView |

```text
ConversationView { id: string, title: string, createdAt: string, updatedAt: string }
ChatMessageView {
  id: string, turnId: string, role: "USER" | "ASSISTANT",
  content: string, sequence: number, createdAt: string
}
TurnView {
  id: string, conversationId: string, requestId: string, turnNo: number,
  status: "PENDING" | "RUNNING" | "SUCCEEDED" | "FAILED",
  createdAt: string, startedAt: string | null, finishedAt: string | null,
  error: { code: string, message: string } | null
}
Page<T> { items: T[], page: number, size: number, total: number }
```

title省略/null为“新对话”，提供时去首尾空白，非空且最多100 Unicode码点；不自动用模型命名，不自动把首条消息全文作为标题。列表按updatedAt DESC/id DESC；消息按sequence ASC/id ASC（第一页是最早消息），空列表返回[]。分页offset必须用long安全计算。

GET仅读取已提交数据，不启动执行、不解密Key、不恢复轮次。TurnView不回传输入哈希、截止时间、内部快照或完整模型响应。失败通过TurnView.error表达，查询失败轮次仍200；SUCCEEDED及非终态error为null。

错误沿用VALIDATION_ERROR(400)、AUTH_REQUIRED等认证码、CSRF_INVALID；新增CONVERSATION_NOT_FOUND(404)、CONVERSATION_TURN_NOT_FOUND(404)。内部Service冲突可用IDEMPOTENCY_CONFLICT(409)、CONVERSATION_BUSY(409)、CONVERSATION_TURN_STATE_CONFLICT(409)，提示均为安全中文。

**T13不发布POST turns、POST messages或任何stream/events接口。** 未映射的发送入口正常不可用，不实现503假占位、不持久化无人执行的HTTP请求、不返回Mock推荐。T14另行冻结发送请求/状态码/结果类型，T15冻结SSE。根文档旧POST messages/stream仅为历史草案，不同时实现两套入口。

## 3. 数据契约：只新增V8

迁移文件：`V8__create_conversation_tables.sql`，不改V1～V7、不操作开发数据库。主键沿用BIGINT identity，时间TIMESTAMPTZ。

- `conversation`：id、user_id（app_user外键CASCADE）、title、next_turn_no（正整数，初始1）、created_at、updated_at；UNIQUE(id,user_id)。按user_id/updated_at/id建立列表索引。
- `conversation_turn`：id、conversation_id、user_id、request_id UUID、input_hash CHAR(64)、turn_no正整数、status、created_at、started_at nullable、finished_at nullable、deadline_at、error_code nullable。通过(conversation_id,user_id)复合外键绑定归属。UNIQUE(user_id,conversation_id,request_id)、UNIQUE(conversation_id,turn_no)、UNIQUE(id,conversation_id,user_id)。
- `chat_message`：id、conversation_id、user_id、turn_id、role、content TEXT、sequence正整数、created_at；通过(turn_id,conversation_id,user_id)复合外键保证消息不跨会话/用户。UNIQUE(conversation_id,sequence)、UNIQUE(turn_id,role)。仅USER/ASSISTANT，不写system/tool/reasoning。
- 状态/角色/正数/非空正文有CHECK；对PENDING/RUNNING的conversation_id建**部分唯一索引**，数据库兜底同会话最多一个在途轮次；过期检索按状态/deadline建立合适索引。
- 本切片不提前存任意JSONB或模型快照。当前都是需要校验/查询的关系字段；T14冻结结构化约束、候选和usage后再决定专属JSONB及追加迁移，不能修改已发布V8。原购物“V9”只是草案，后续按实际迁移序号冻结。

库约束与Service共同保证：PENDING无started/finished/error；RUNNING有started、无finished/error；SUCCEEDED有started/finished、无error；FAILED有finished和安全error_code（started可空）。SUCCEEDED必须与唯一助手消息在同一事务完成；数据库不能以跨表CHECK保证的规则由Service及集成测试负责。

## 4. 内部Service契约与状态机

实现可自定项目类名，但必须提供以下明确能力，返回项目DTO/VO，不暴露Entity/Mapper或供应商类。

1. `registerTurn(conversationId, requestId, content)`：UUID须规范格式；正文非空白、最多4000 Unicode码点，保留原始正文、不trim/改写。同内容指精确字符串一致；SHA-256(UTF-8原文)加原文比较，不能仅凭哈希判定。结果含TurnView和created标志，重放created=false。
2. `startTurn(conversationId, turnId)`：只有PENDING且未过期才能转RUNNING；只返回一次成功的开始资格，后续重复开始返回状态冲突，不能把RUNNING当再次执行许可。
3. `succeedTurn(conversationId, turnId, answer)`：answer非空白、最多8000码点；只有未过期RUNNING可转SUCCEEDED，同一短事务插入唯一ASSISTANT消息与更新状态。不得将调用者任意异常/Prompt当答案写库。
4. `failTurn(conversationId, turnId, failureCode)`：只允许PENDING/RUNNING转FAILED，错误码限定项目枚举，不能接受供应商原始消息。终态不可覆盖；无自动重试/重置到PENDING。
5. `getTurn`：按当前用户和会话边界读取。
6. `recoverExpiredTurns(conversationId)`：只处理当前用户该会话，过期在途轮次转FAILED/RUNTIME_INTERRUPTED，不生成助手消息、不重放外部调用。注册新轮次前在同一事务调用等价恢复逻辑，避免旧任务永远堵住会话。

初始deadline为注册时数据库时间+120秒，start不延长；后续T14整轮上限要低于此值。数据库时间为过期判定权威，开始/成功的条件更新必须包含deadline未过期，不能只等恢复函数跑完才拒绝迟到结果。T13不新增后台执行器、定时任务或启动全库清理；未来恢复调度另行接线，当前GET不会把过期轮次自动改成失败。此为明确取舍，不宣称已完成真实进程重启验收。

失败枚举预留：RUNTIME_INTERRUPTED、CREDENTIAL_NOT_CONFIGURED、CREDENTIAL_SERVICE_UNAVAILABLE、MODEL_AUTHENTICATION_FAILED、MODEL_RATE_LIMITED、MODEL_TIMEOUT、MODEL_UNAVAILABLE、MODEL_INVALID_RESPONSE、RETRIEVAL_FAILED、RESOURCE_LIMIT、EXECUTION_FAILED。映射为固定中文提示，不保存异常链或用户输入。T13不负责将实际供应商失败映射进这些码，T14接入。

## 5. 并发、事务与顺序

所有写操作先按id+可信user_id锁conversation父行（FOR UPDATE），锁顺序统一为父会话→轮次→消息。只锁短数据库操作，绝不能包住模型等待。READ COMMITTED足以配合此显式锁；不依赖单机synchronized、内存map或Redis。

注册流程：锁定并校验归属→恢复该会话已过期轮次→查同requestId；已存在时比对原文和哈希，同内容返回原轮次，包括FAILED，不重启；异内容409。无同键时检查仍在途轮次，存在则CONVERSATION_BUSY且不写新用户消息；否则从next_turn_no分配顺序，插入PENDING与USER消息、递增计数并更新会话时间，原子提交。

消息sequence为2*turnNo-1(USER)、2*turnNo(ASSISTANT)，缺少失败轮次的助手消息允许有空档；序号不复用。计数与sequence必须检测整数溢出并安全拒绝，不能数据库溢出成500。完成/失败/恢复更新会话updated_at，读操作不更新。

恢复、start、succeed、fail都遵循同一父行锁顺序及状态条件，避免恢复与完成竞争把旧答案写入终态。同键并发最多一次created=true、一次USER消息；同会话异键并发最多一个被接纳，另一方忙冲突；不同用户/不同会话互不串数据。

这些约束只防止本地重复执行资格，不承诺供应商计费恰好一次。事务提交后进程崩溃可能留下消息/轮次，后续按过期状态恢复，不自动再次收费。
