## 2. 关键实现选择

V6 的 `recipe_cook_record` 使用 BIGINT identity 主键、当前用户和菜谱外键、UUID 幂等键、`TIMESTAMPTZ` 服务器时间及可空 `SMALLINT` 评分。`UNIQUE(user_id,idempotency_key)` 是并发和重试的最终约束；`rating BETWEEN 1 AND 5` 防止绕过应用层。用户删除时级联删除私人事件；菜谱删除采用 `RESTRICT`，避免已有历史指向不存在的菜谱。未来若需要硬删菜谱，须先定义历史留存策略。索引 `(user_id,recipe_id,cooked_at DESC,id DESC)` 支持按用户和菜谱聚合、查最近评分。

Service 先严格检查菜谱 ID、UUID、评分，再从 `CurrentUserService` 取用户，调用 `RecipeReadService.requireVisible`。不可见或不存在均为 404。事务中的 `INSERT ... ON CONFLICT DO NOTHING` 返回写入行数；新事件 201，冲突则读取原行并比较菜谱和评分，同内容 200、不同内容 409 `IDEMPOTENCY_CONFLICT`。不在 PostgreSQL 唯一约束异常造成的失败事务中继续查。重放返回原 ID、服务器时间和评分，不更新事件，也不累计次数。幂等键只在同一用户范围唯一；同菜再次真正做完必须用新键。

历史接口通过总数查询和一条分页聚合查询返回每菜一张卡，不逐卡查询。`cookCount` 为事件数，`lastCookedAt` 为最大完成时间，最近非空评分按 `cooked_at DESC,id DESC` 查出。排序 `lastCookedAt DESC,recipeId DESC`，熟悉度 1～2 初尝、3～5 熟悉、6 起常做。标签仅用于展示，不能等同喜爱或真实技能；收藏仍由原表独立决定。Controller 只调用 Service，响应只用 VO。

在 Spring Boot 4 的 Jackson 3 运行时，默认把 JSON 小数映射到 `Integer` 时曾将 `1.5` 转为 `1`。最终 DTO 以 Jackson 3 `JsonNode` 保留评分原类型，Service 只允许 `null` 或整数，再检查范围；测试已覆盖小数 400。此选择比全局改变 JSON 转换规则更局部，兼容现有 T7/T9 请求。
