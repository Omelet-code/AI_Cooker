## 实现

- 将详情页使用的完成确认、评分、取消、重试与清理状态集中在 useCookingCompletion。Vue 页面模板和测试调用同一套页面逻辑，不复制处理函数。
- 普通首次成功和重试成功共用 clearCompletion，关闭确认框并清空评分。未知或失败时不清草稿；重试始终委托 Store 使用现有 pendingCooking，因此继续复用原 UUID、菜谱和评分。
- 异步成功只在当前菜谱 ID 和当前用户 ID 与操作开始时一致时清理局部状态。菜谱或用户变化时同步关闭旧确认并清空旧评分，避免旧页面草稿泄漏到新页面。
- 取消确认只清理尚未提交的本地状态，不创建烹饪事件。

新增回归通过页面实际使用的 useCookingCompletion 驱动受控 API Promise，覆盖：

1. 取消不发记录请求。
2. 首次超时后以相同 UUID/评分重试成功，确认框关闭、评分清空。
3. 用户再次主动打开确认后才创建新操作，新操作使用新 UUID；未重新选择评分时提交 null。
4. 重试再次未知时，评分和 UUID 保持不变，后续重试仍发送相同请求。
5. 身份切换期间旧响应不能清除新用户填写的评分。
6. 菜谱切换会清除旧草稿；旧菜谱重试迟到成功不会在新页面打开确认框。

测试使用当前 Vue/Vitest 依赖，没有新增浏览器模拟库。它是受控 Promise 的页面逻辑自动化回归，不等同真实浏览器人工验收，也没有调用后端或数据库。

## 学习点与自检

- 状态归属：Store 管理请求及幂等键，页面控制弹窗和评分；两层需要在成功时协调清理。
- 超时语义：第一次请求超时不能证明服务端失败，因此重试必须保留原请求内容。
- 上下文隔离：异步结果应用前比较操作发起时的菜谱和用户身份，防止旧视图清理新视图状态。
- 自检：失败后是否保留旧请求？是；重试是否重新造 UUID？否；重试成功后是否自动开启下一次确认？否；取消是否写入？否；用户主动再次确认是否生成新事件？是。
