## 4. 实现与设计选择

- 可信显式viewerUserId：验证正ID及账号存在，复用身份公共Service，不跨读身份Mapper，不读取线程身份，不使用档案返回值推断人数。
- RANDOM：两角色分类并集与用户分类求交，复用资格Service读完整池；超过1000返回RESOURCE_LIMIT，稳定ID排序后按角色种子抽样，重复输入可复测。空交集不调用无限制SQL，不调用T5或Embedding。
- SEMANTIC：每角色至多一次原生产T5Service、limit≤20、最多两次。去重并按可信角色过滤，保留旧排名，短缺不追加检索。
- 返回前通过recipe公共Service复核可见性、资格、角色及当前指纹。候选入口NOT_SUPPORTED，事实/复核REQUIRES_NEW＋REPEATABLE_READ独立短事务，外部等待不持有事务。
- 四类参数化批量事实SQL，各自带可见性边界；保留全部原料行、标准ID与状态、步骤/厨具/补充原文、源文档及源哈希，整批任一不可访问安全失败。
- 折算只针对已知正份数、单一非负数量、明确匹配单位，以BigDecimal乘除、scale6/HALF_UP输出REFERENCE_SCALED。原量不改，分数计数不取整；区间/适量/未知保留原说明和原因。
- 汇总只按REVIEWED标准ID＋完全一致单位代码/标签＋optional合并，逐来源保留待确认；不换单位、不按名称相似合并。
- 指纹包含当前结构化事实和角色版本，并非只依赖Markdown哈希；真实PG覆盖材料原行、步骤、厨具、份数改变后的失效。
