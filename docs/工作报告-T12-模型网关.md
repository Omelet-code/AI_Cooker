# T12 模型网关工作报告

## 目标与边界

在 Agent 模块建立一次同步、受限的 DeepSeek 模型调用入口。每次调用读取当前用户的 LLM Key，并仅用于本次请求。实现遵循任务卡与 ADR-008：固定官方 HTTPS 地址、固定 `deepseek-flash` 模型，不接受调用方覆盖供应商 URL 或模型，不缓存明文 Key，不做重试、工具调用或流式输出。

本切片没有创建 Controller、聊天记录、数据库表或前端功能，没有调用真实 DeepSeek / 百炼服务，也没有提交、推送或部署。

## 实现内容

- 在 `backend/pom.xml` 引入项目锁定版本的 Spring AI DeepSeek 适配器。
- 在 `agent` 模块增加同步 `ModelGateway`、输入/输出 DTO 与无敏感异常分类。
- `ModelGatewayServiceImpl` 先限制输入，再校验当前身份，调用 T8 的 `LlmCredentialService.decryptCurrentUserCredential()`；之后为单次请求创建客户端并只调用一次 `ChatModel.call`。
- 输入最多 16 条消息、累计最多 20,000 个 Unicode 码点；只允许 system/user/assistant 角色。JSON 模式强制 JSON response format，验证返回内容是单个合法 JSON 值。无论 TEXT 或 JSON，均先以大小写不敏感方式拒绝 `finish_reason=LENGTH`。
- 客户端固定官方 `https://api.deepseek.com/chat/completions`、`deepseek-flash`、禁用 thinking、最多 2048 个输出 tokens、连接超时 5 秒、响应超时 30 秒，并显式将重试次数设为 0。
- 将认证、凭证缺失/解密失败、供应商鉴权、限流、超时、供应商不可用和无效响应映射成不携带异常 cause 的内部错误类型。供应商 401/403 不会映射为应用登录失效。
- 将 Spring AI DeepSeek 模型日志级别设为 ERROR，避免其空响应 WARN 日志输出 Prompt 内容；输入 DTO 的 `toString()` 也不返回消息正文。

## 设计取舍与限制

- 客户端每次创建，避免一个用户的 Key 被复用到另一个用户的调用。
- 当前没有聊天/消息持久化、对话轮次编排、提示词模板、检索上下文、工具、SSE 或控制器。这些需要后续单独授权。
- Java `String` 不保证调用结束后底层字节立即清零；实现通过缩短明文 Key 生命周期并禁止缓存、日志和 DTO 暴露来降低风险。
- 真实供应商连通性、账号额度和响应兼容性没有验证；本报告不代表收费 API 验收。
- 需主架构 Agent 审查后签收；当前未完成提交或主分支集成。
