## R1（P2）：成功重试会重新打开完成确认弹窗

文件：`frontend/src/views/RecipeDetailView.vue`，第15～21行与第47行。

正常确认成功时，confirmCooking会清showCompletion与selectedRating；但首次提交超时后showCompletion仍为true，弹窗仅因pendingCooking存在而隐藏。retryCooking只await Store重试，没有执行成功清理。Store成功时pendingCooking变null，模板 `showCompletion && recipe && !anyPending` 再次为true，于是确认框自动重新出现，原评分仍保留。

复现路径：打开完成确认→选5分→首次请求超时/结果未知→点击“用相同内容重试”→服务端返回已有事件成功→确认框自动再次出现。用户再次按确认会调用completeCooking创建新UUID，变成另一事件；这是重复计数风险，而非数据库同键幂等失效。

主架构在内存读取实际源码confirmCooking/retryCooking函数，使用真实Vue ref与可控Store返回模拟结果未知和成功，未修改生产文件，输出：

```json
{"beforeRetry":{"showCompletion":true,"pending":"unknown","dialogVisible":false},"afterSuccessfulRetry":{"showCompletion":true,"pending":null,"selectedRating":"5","dialogVisible":true}}
```

这证明实际页面处理函数及模板条件的状态路径，不冒充浏览器操作。现有Store测试证明同键重试和新操作新键，但没有覆盖成功重试后的页面弹窗关闭；现有详情SSR测试仅检查食材文本/可选标识。

建议修复：让首次成功和重试成功共用完成清理，确保成功重试不会自动开启下一次确认；如有路由变化，清理只能作用于相应操作。补实际页面处理/渲染交互回归，证明超时→同键重试成功后弹窗关闭、评分清空，只有用户再次主动点击“完成烹饪”才能新建事件。当前仅审查，不修改或派发。
