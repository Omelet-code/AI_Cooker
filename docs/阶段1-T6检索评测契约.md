# 阶段 1 T6：检索质量与性能评测契约

> 状态：T6 已完成验收。用户于 2026-09-29 对整套候选标签作总体认可；同日单次授权的生产 Service 入口真实混合复测达到质量、性能和独立硬条件门槛。再次收费运行仍需重新授权。
> T6 不授权 T7 或任何后续业务功能。

## 1. 目标与范围

建立可复现的检索质量和性能评测；不改 `RecipeSearchService` 生产排序。实现仅位于 `backend/src/test` 与本 T6 文档/报告。固定输入为 HowToCook `1.6.0`、commit `a0b14bd`（当前本机数据库的 372 道菜谱、1850 个 READY chunk），索引版本 `text-embedding-v4:1024:template-1`。

常规 `mvn clean test` 完全离线。手动评测类只有同时显式设置 `cooker.t6.enabled=true` 才运行，Flyway 关闭，Hikari 连接设为只读。真实数据库建议再使用只读账户。默认词法单路模式不调用 Embedding Provider。混合模式必须使用真实查询向量；缺少向量或调用失败时该次记为失败，不会用词法结果冒充混合结果。

## 2. 评测数据

固定集：`backend/src/test/resources/retrieval-evaluation/t6-dataset-v1.json`。包含 40 条相关性查询，覆盖精确菜名、原料及别名、短中文/模糊菜名、自然语言偏好、时间、厨具与排除原料；另有空结果和权限边界用例，不纳入相关性指标分母。每条相关性记录含原始 query、结构化条件、候选相关菜谱 ID、候选理由、分组及数据/索引版本。

固定标签版本为 `t6-labels-v1-2026-09-29`。用户于 2026-09-29 表示整套候选总体没有问题，批准范围是全部候选 ID 与理由的整体认可，不代表存在逐条审定记录。数据文件保存整体审定日期、范围及 ID/理由集合 SHA-256，测试必须校验冻结摘要。当前数据库只含公开系统菜谱，私有权限边界标为不适用，并引用既有 T5 合成权限测试；不得把“没有私有样本”写成检索通过。

## 3. 指标与门槛

- Hit@3：每条查询的前 3 名至少包含一个相关菜谱的比例；目标 ≥75%。
- Hit@5：每条查询的前 5 名至少包含一个相关菜谱的比例；目标 ≥80%。
- Recall@5：每条查询 Top5 找到的相关菜谱数 / 该条相关标签数，再对查询做宏平均。
- MRR@10：每条查询第一个相关菜谱排名倒数（前 10 无命中为 0），再对查询做宏平均。
- 有效样本数只计带相关标签的 40 条查询；边界样例不进入分母。按评测分组另外给出以上指标。
- 时间、厨具、排除食材违规数必须为 0；零结果、Embedding 降级、超时和失败另行统计。
- 预算与家庭库存覆盖率不属于 T5 Criteria，留待后续业务闭环验收。

词法单路和真实混合模式只能使用同一 JSON 数据集。真实混合指标仅可来自真实 `text-embedding-v4` query embedding。

## 4. 性能口径

- 质量和延迟评测必须调用生产 `RecipeSearchService.search`；禁止在评测主循环直接调用 eligibility Service、Mapper 或 `fuse`。
- 查询 Embedding p50/p95：测试层装饰 `QueryEmbeddingService` 计时，只统计对应的 Provider 调用时长；词法模式在测试装饰器中屏蔽远程请求。
- 端到端 p50/p95：直接计生产 `RecipeSearchService.search` 的单次总耗时；本地链路样本按同次 Service 总耗时减去装饰器测得的 Embedding 时长。报告说明这一口径，不把网络时间冒充数据库耗时。
- 默认每条查询 3 次预热、5 次正式计时。混合模式以每次 embedding 请求实际调用次数为准；40 条查询在 3+5 设置下最多 320 次调用，失败的尝试同样计数。请求费用未知时只能写“未知”，不可推算或虚构。
- 报告需保存运行 Java/操作系统/PostgreSQL 信息、样本数、重复次数、超时和失败数。p95 是当前运行样本统计，不等同多机稳定容量保证。查询向量缺失、维度错误、非有限值或 Provider 异常会令该轮评测失败，不接受生产 Service 静默词法降级作为混合结果。

## 5. 手动运行

先准备已导入 T5 固定快照的 PostgreSQL 只读连接环境变量 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`，然后在 `backend` 目录运行：

```powershell
mvn "-Dtest=T6RecipeSearchEvaluationTest" "-Dcooker.t6.enabled=true" "-Dcooker.t6.mode=lexical" test
```

词法运行由测试层装饰器强制屏蔽 Provider，不执行迁移、不调用收费 API，结果写入 `backend/target/t6-evaluation/evaluation.json` 与 `report.md`。混合运行必须先由主架构会话向用户说明请求数（默认 320）和未知费用风险，获得该次运行明确批准后才可启用 `mixed`。环境变量或本契约本身不构成付费运行授权。

## 6. 通过与交付

指标即使低于门槛，也如实给出逐条 Top10、冻结标签、命中原因和失败归因，不调整门槛、不改生产排序迎合样例。历史 320 次真实混合报告由旧评测直接编排入口生成，仅作历史基准。2026-09-29 经用户单次授权的修订版复测经过生产 `RecipeSearchService.search`：40 条有效查询，320 次真实 query Embedding，Hit@3 75.0%、Hit@5 87.5%、本地 p95 122.449ms；所有正式查询无失败/超时，独立硬条件违规为 0，两个适用边界均通过。无私有菜谱样本，因此权限边界在真实快照中仍为不适用，由既有 T5 合成测试覆盖。
