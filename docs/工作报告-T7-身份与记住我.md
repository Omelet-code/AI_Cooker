密码由 Spring Security `Argon2PasswordEncoder` 哈希，数据库只留哈希；续期令牌来自 `SecureRandom` 32 字节，数据库只留 SHA-256 哈希。访问 JWT 由 HS256 签名并验证签发方、受众、签发/到期时间。续期事务先用条件 UPDATE 撤销旧令牌，再插入新令牌；30 天记住我期限是本次登录的绝对上限，轮换不续命。失败竞争只返回 `REFRESH_CONFLICT`，不清除 Cookie。退出撤销当前续期令牌并清 Cookie；已签发访问 JWT 仍可能在剩余有效期内有效。

## 限制、待验与复现

- **浏览器证据边界**：主架构已在 real 模式经 Vite `/api` 代理验证注册、勾选记住我登录、刷新恢复和退出，并核对 PostgreSQL 持久化。浏览器关闭重开、访问 JWT 真正到期后的续期及双标签并发 Set-Cookie 尚待验证；不能把自动化测试当成这些场景的浏览器签收。
- 当前进程的 JWT 密钥是启动时生成的临时环境值，未写文件。重启或部署时必须由安全环境注入稳定密钥；旧访问 JWT 在密钥变化后失效，但有效续期 Cookie 可尝试换新。生产要启用 HTTPS 并保持 Secure Cookie。
- 此版本只撤销当前续期凭证，不实现全设备已签发访问 JWT 立即撤销。登录未知用户名与密码错误响应相同；CPU 耗时仍可能不同，尚无登录限速和设备管理。
- 当前 Cookie `SameSite=Lax` 适用于冻结的同源 Web 方案；跨域前端须重新设计 Cookie/CSRF/CORS 契约。
- 复现：在指定工作树 `backend` 下把 `JAVA_HOME` 指向 JDK 21，运行 `mvn test`；Docker Desktop 可用时 Testcontainers 自动执行真实数据库测试。访问 8080 的 `/api/auth/csrf` 获取 CSRF 后以 `X-XSRF-TOKEN` 调用注册/登录；不将密码、令牌或 Cookie 复制进报告。后端真实运行详情见 `docs/运行状态-阶段2后端.md`。
